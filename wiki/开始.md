# Scholay 内容维护

[按线上导航浏览](导航.md) · [全部词条](索引.md) · [XMind 视图](Scholay.xmind)

这个项目是 Scholay 内容的长期底稿。你在本地手动改的正文是第一手内容；网站资料用于本次初始化，后续网站变动先比较，由你决定是否采纳。

## 用 Obsidian 写正文

在 Obsidian 中选择“打开文件夹作为仓库”，选择本项目根目录 `scholay`，打开本页。通过导航或索引进入词条，在 `pages/` 中直接编辑 Markdown。

每篇词条只保存一份；网站导航中的多个入口会指向同一篇。8 个内容分类及 16 组网站导航均来自 2026-09-06 线上配置。导航和索引由 catalog 生成，正文由你手动维护。

## 用 XMind 看结构、改正文

打开 `Scholay.xmind`。第一个画布是网站导航，其余 8 个画布对应内容分类。导航节点可跳转到对应词条；每个词条的 Note 保存完整 Markdown 正文，直接在 Note 中编辑并保存即可。

Note 保留 Markdown 标题、表格和链接，不会在 XMind 中完全渲染成网页。页面属性保存在 Markdown 顶部，不需要在 XMind 中填写。

本次先支持稳定的词条正文双向同步。新增/删除词条、调整分类、修改导航或节点标题时，要同步调整 `catalog.json`；同步器发现 XMind 结构变化会停止，交由人工核对。

## 同步

需要 Python 3 和 Node.js，无第三方运行依赖。从项目根目录运行：

```bash
python3 tools/wiki/sync.py status
python3 tools/wiki/sync.py auto
python3 tools/wiki/sync.py verify
```

也可按方向执行 `to-xmind` 或 `from-xmind`。两端都改时不自动选择较新文件，避免丢字。每次覆盖前备份到 `.local/wiki-sync/backups/`。不要手动删除状态来绕过冲突检查。

可以双击根目录的 `启动双视图同步.command` 持续监听已保存文件。XMind 外部更新后请重新打开；不要把旧窗口中的内容再次保存覆盖新版。首次在其他电脑克隆后，先运行 `verify` 校验并建立该电脑的同步基线。

## 新建词条

1. 在 `pages/<分类>/` 新建 `.md`，参照同分类页面填写顶部属性、稳定 slug 和正文 H1。
2. 在 `catalog.json` 的 articles 增加 slug、title、category、path；按需加入 navigation，多个导航入口可以引用同一个 slug。
3. 运行 `python3 tools/wiki/export.py` 更新目录，再运行 `sync.py to-xmind` 和 `sync.py verify`。

## 同步到 GitHub Wiki

```bash
python3 tools/wiki/export.py --github
python3 tools/wiki/prepare-github.py
```

第一步生成 96 篇词条及 Home、侧栏、页脚；第二步在 `.local/github-wiki-checkout/` 准备独立 Wiki 仓库的可审阅修改。两步都不会 push。维护好并审阅后，再提交并推送主仓库与 Wiki 两份仓库。

2026-09-06 核查时，主仓库已启用 Wiki、当前账号有管理及推送权限，但 `scholay.wiki.git` 在 SSH 和 HTTPS 下均返回 Repository not found。可能尚未创建首个 Wiki 页面；需要在 GitHub 的 Wiki 页面完成初始化后再重试。当前只有本地导出，没有声称线上同步完成。

## 来源和边界

- 初始资料：[Scholay Wiki](https://www.scholay.com/wiki/) 和官方 `.md` 导出。
- 原始 Markdown、API 正文、分类和导航快照位于 `sources/online/2026-09-06/`，有逐篇 SHA-256 收据。
- 本地正文只把站内链接转换为可点击的本地链接；原始快照不变。
- 官方 Markdown 将网页交互组件导出为“界面示意”说明，本地没有对应的动态界面或截图。原生 API 的 `body_md` 保留了组件引用，供将来恢复使用。
- 当前没有修改线上 Scholay Wiki，也没有推送主仓库或 GitHub Wiki。
