# 把论证立起来:贡献、桥、叙事三处关节

## 第一性原理:一篇论文是一条待读者相信的推理链

读者默认怀疑。写作的目标不是「陈述我们做了什么」,而是为结论铺一条读者无法反驳的路。链条最常断在三个关节:贡献说不出比昨天多了什么(delta 缺)、证据到结论之间那座桥没画在纸上(warrant 缺)、引言凿的问题和后文给的方案对不上(叙事不咬合)。下面逐个给出诊断动作与改写句骨。

先划边界:如果推理链本身完整,只是动词选得过硬或过软(单组实验配「证明」、「所有场景」全称断言),那是措辞强度问题,交给校准强度的那一条;这里只管**结构缺件**——缺的那句话本身还没写出来。

## 一、叙事弧:Story → Problem → Solution 必须咬合

好的引言前三段有清晰的能量走向:

- **Story**:锚定一个读者点头的共识,越具体越好,最好落到一两篇代表作 [@key] 上;
- **Problem**:在共识里凿一道真实裂缝——一个具体失效条件或未回答的量,不是「研究不足」「值得进一步探索」;
- **Solution**:你这一步正对那道缝。你解决的,恰是你凿开的。

❌ 深度学习近年发展迅速。许多研究者研究了分子性质预测 [@a; @b; @c]。图神经网络被广泛使用。本文提出一个新模型。

✅ 图神经网络已成为分子性质预测的默认工具 [@a; @b]。但现有模型都假设训练与测试同分布,而药物发现的真实场景恰恰要对**未见骨架**外推——此时报告的准确率会掉 20 个百分点以上 [@c]。本文提出显式建模骨架偏移的方法,把外推场景的误差拉回同源水平。

🔍 只改的一个特征:把并列的领域综述换成「共识→裂缝→正对裂缝的方案」因果链——裂缝被量化(掉 20 个点),方案的词汇(骨架偏移)与裂缝的词汇(未见骨架)互相咬住。

两个自检探针:

1. 每段末尾追问「所以呢」。答不上的段落,要么删,要么把它与裂缝的因果写出来。
2. 把引言的 Problem 段和摘要的 Solution 句并排放,圈出重合的名词。**没有重合名词,就是不咬合**——此时优先改 Problem 段(裂缝凿错了位置),而不是改方案描述。

凿裂缝的句骨:「尽管___已成共识 [@___],但在___条件下,___仍未解决/会退化到___。」注意凿的是「未解决的条件」,不是贬低前人——他人工作的转述保持中性归纳。

## 二、把那座没画的桥画出来(warrant)

一个完整主张至少有三个零件:claim(要读者信的结论)、data(手上的证据)、warrant(把 data 连到 claim 的推理规则);再加两个让它可信的配件:qualifier(成立范围)与 rebuttal(已知反例与边界)。作者几乎总把 warrant 留在脑子里——因为对你太显然。但读者凭什么信这份 data 支撑这个 claim?那座桥必须画在纸上。

诊断动作:对文中每个「因此/表明/说明/这意味着」回读一遍,自问「读者要额外相信什么,才接受这一跳?」把答案写成一句话——那句就是漏掉的 warrant,补进正文。

❌ 我们的方法达到 92.3% 准确率,因此优于基线。

✅ 在相同数据划分与参数预算下,我们的方法达到 92.3%,较最强基线高 3.1 个点;该差距超过五个随机种子的标准差(±0.6,见 [@tbl:main]),并跨过临床可用的 90% 门槛。在外部队列上,优势收窄至 1.2 个点(见 [@fig:transfer])。

🔍 只改的一个特征:「因此」两侧本来隔着三层没写的推理(差距超过噪声、对比公平、提升有意义),改后每一层都落成可核查的句子;成立范围与已知反例主动摆出,读者会想到的问题被抢先回答。

「因此」下面最常缺的三层,逐层配句骨:

- **差距>噪声**:「该差距超过___次重复的标准差(±___),见 [@tbl:___]。」
- **对比公平**:「两组在___、___上保持一致,仅___不同。」
- **提升有意义**:「___个点的提升意味着___(下游影响),跨过___门槛 [@___]。」

先摆反例不是示弱:读者迟早会想到它,你先写出来,它就从「漏洞」变成「边界」,顺带把结论圈进一个守得住的范围。通用补桥句骨:「该结论成立,还需读者相信___;我们通过___排除了这一疑虑(见 [@fig:___])。」

## 三、贡献条:可证伪 + So-What + delta

无效贡献是不可证伪的名词短语——「提出一个新架构」里的「新」无法被任何实验推翻,读者得不到任何可检验的承诺。三问逐条过每一行贡献:

1. **可证伪**:一个实验能推翻它吗?不能→补数字;
2. **So-What**:谁因此能做成什么?答不上→补下游收益;
3. **delta**:相对最近最像的那篇 [@key],多出的一句话是什么?答不上→要么去找,要么承认这条不成立。

❌ 我们提出了 FooNet,一个用于分子性质预测的新架构。

✅ 显式建模骨架偏移后,未见骨架上的预测误差从 0.42 降到 0.25 MAE(见 [@tbl:ood]),使虚拟筛选首次能信任外推打分;相比 [@bar2025],我们无需目标域标注即取得该效果。

🔍 只改的一个特征:主语从「我们的劳动」换成「读者的收益」——数字给出验伪把手,下游一句回答 so-what,与 [@bar2025] 的对比一句写明 delta。

铁律:「我们实现了一个系统/进行了大量实验/设计了一个模块」属于方法节,不是贡献。贡献是这些动作兑现出来的、读者能带走的价值。改写模板:「因为做了___,现在___成为可能/___的代价从___降到___(相比 [@___],省掉/多出___)。」

delta 找不到时的三个去处:

- **换更近的对比对象**——常常是相关工作里你最不想提的那篇,读者恰恰会拿它来对照;
- **缩小声明范围直到 delta 成立**——「在无标注外推场景下首个达到 X」比「性能领先」守得住,范围限定反而让贡献变硬;
- **合并**——若两条贡献答出的是同一句 delta,它们本来就是一条。

## 四、整链自检(改完跑一遍)

1. 摘要的 Solution 句与引言的 Problem 段,名词有没有重合?
2. 全文搜「因此/表明/这意味着」,每一处能否指着一句已经写下的 warrant?
3. 每条贡献:数字在哪、谁受益、比 [@___] 多什么,三问全过?
4. 结论节有没有偷偷抬高声明(引言说「在某条件下降低误差」,结论变成「解决了外推问题」)?链条两端的承诺必须是同一个;若差的只是动词档位,交给校准强度那条处理。

## 别动/豁免清单

- **动词强度与全称限定**(证明/表明/提示、所有/总是)不归这里——结构完好只是措辞过硬或过软时,去校准强度的那条;
- **方法节的客观步骤**保持中性描述,别改写成推销;
- **已达标的贡献条**(有数字、有收益、有对比)别为改而改;
- **[@key]、[@fig:x]、[@tbl:x]、$...$ 原样保留**,只动它们周围的散文;需要新的证据锚点时用 [@___] 占位标出,绝不编造引用键;
- **他人工作的转述**只做中性归纳——凿裂缝凿的是「未解决的条件」,不是前人的失误。
