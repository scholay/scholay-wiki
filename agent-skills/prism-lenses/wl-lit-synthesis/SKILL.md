生成动作:把「写综述节」拆成七步阶段协议逐步推进,每一步向用户交付一个可确认的中间产物,绝不一口气从检索跳到成文。

① 纳排标准:先用 2-3 句向用户确认范围——主题边界、时间窗、纳入什么类型(方法/应用/综述)、排除什么。未确认不检索。
② 按视角轮检索:视角 = 问题定义 / 方法谱系 / 评测与基准 / 局限与批评,每轮 1 个视角、2-3 条检索式;查到的真实论文当轮写进 references.bib(真实元数据,绝不编)。
③ 试筛确认:先筛 10 篇给用户看「纳/排 + 一句理由」的清单,用户确认标准对齐后再扩大。
④ 主题聚类:把入选文献按主题/方法路线聚成 3-6 簇,给出「簇名 + 各簇文献 + 簇要回答的问题」的大纲,请用户拍板。
⑤ 逐簇成段(每簇一轮):先从该簇每篇文献摘出支撑句(quote-then-cite-then-write:先有摘录,再落 [@key],最后成句);段落 = 共性判断 → 代表工作 → 共同局限 → 与本文关系。条件于已写段落,不重复。
⑥ 补检索:发现明显缺口可补 1 轮检索,封顶 1 轮,防无限扩张。
⑦ 收尾:全节按 wl-related-work-structure 的定位句纪律过一遍——每簇末尾必须有「本文站在哪」。

铁律:每个带 [@key] 的断言必须能指回该文献的具体摘录;只有摘要可读的文献,断言措辞降级(「据其摘要」「该文报告称」),绝不代替全文下结论。

❌ 逐篇流水账:「A 提出了 X。B 提出了 Y。C 改进了 Z。」
✅ 簇式综合:「早期工作把该问题当作序列标注(A;B),共同假设标签条件独立;这一假设在长程依赖下失效(C 的消融),后续工作转向图结构建模(D;E)。本文属后者,但去掉了 D 依赖的人工对齐。」
🔍 只改了组织方式:从「一篇一句」变成「共性判断 + 证据 + 局限 + 定位」,引用键一个没丢。

别动/豁免:不足 20 篇的普通 related work 别启用本协议(直接按 wl-related-work-structure 写);用户已给定文献清单时跳过 ①-③ 从 ④ 起;每步的用户确认不可跳过(范围错了后面全废)。

## 深入

### 为什么必须分步且每步可确认

综述节的失败极少发生在句子层,几乎都发生在**范围与组织**:检索范围偏了、纳排标准漂了、聚类维度选错了——这些错误一旦带到成文阶段,返工代价是整节推倒。七步协议把三个最贵的决策(范围、纳排、聚类)前置成用户可拍板的轻量产物:两句话的标准、十行的试筛清单、一页的簇大纲。确认成本每次不到一分钟,却把「写完发现方向错了」的风险清零。

### 视角轮检索:为什么不一次查完

一条检索式只能照亮一个侧面。按「问题定义 → 方法谱系 → 评测与基准 → 局限与批评」四个视角分轮检索,每轮 2-3 条检索式,有三个好处:
- 覆盖面结构化:四个视角合起来天然对应综述节的段落骨架;
- 每轮体量可控:检索结果当轮筛、当轮入 references.bib,不会一次涌入 60 篇无从下手;
- 「局限与批评」视角专门找反面证据——只查支持性文献的综述会被审稿人一眼看穿。

### quote-then-cite-then-write:溯源纪律

成段的顺序必须是:先把该簇每篇文献里支撑本段论点的**原始表述**摘出来(全文可读的摘原文;只有摘要的摘摘要句),再决定哪句配哪个 [@key],最后才写自己的综合句。反过来(先写观点再找文献贴)是幻觉引用的温床——句子会说出文献没说过的话。

强度分级:
- 全文可读(用户文献库有 PDF):可以做具体断言(「其消融显示去掉 X 后 F1 降 4.2」);
- 仅摘要可读(检索新得):措辞降级为「据其摘要」「该文报告称」,数字只引摘要里出现过的;
- 只有标题:不做内容断言,最多作为「相关方向存在」的存在性引用。

### 逐簇成段的段落骨架

每簇一段(长簇可两段),四拍:
1. **共性判断**(主题句):这簇工作共享什么思路/假设——这是你的综合,不是任何单篇的复述;
2. **代表工作**:2-4 篇点名,一篇一个从句或短句,带 [@key];
3. **共同局限**:这簇整体缺什么(最好有具体证据:某篇的失败案例、某个未覆盖的设定);
4. **与本文关系**:本文继承什么、区别什么(定位句,wl-related-work-structure 的纪律)。

### 综述场景的检索工具选型

七步协议里的检索不是只有一个 `search_papers`,按目的选最省、最准的入口:

- **领域景观 / 趋势**(哪些年、哪些机构、哪些子主题在集中发力)→ `group_works` 把一批结果分桶,直接支撑「近几年综述」的分布性判断,别逐篇数;
- **由种子集扩展相关工作**:第②步查到的入选文献攒成种子池 → `recommend_from_pool` 顺整池共性扩出同类;单篇找近邻用 `get_related_works`——两者都能补上纯关键词搜漏掉的旁支;
- **一次水合多个已知 ID**(如第③步筛出的一批文献要补全元数据)→ `get_papers_batch`,别逐篇取;
- **quote-then-cite 要「有出处的原始摘录」** → `search_snippets` 取可溯源的原文片段,尤其是只有摘要可读、又想为某句配具体证据时——它直接给回带出处的段落,契合「每个 [@key] 断言可指回具体摘录」的铁律。

### 与相邻能力的边界

- 组织与定位的**通用**纪律(簇数 3-5、流水账诊断、漏斗方向)在 wl-related-work-structure——本协议第⑦步显式调用它;
- 「是否公正对待前人、有没有稻草人」在 wl-rl-related-work-fairness——成文后建议用户跑一遍;
- 引用条目的真实性(minicod 检索、绝不编造)是常驻纪律,本协议只是在其上加了「断言可溯源到摘录」这一层。
