# 图与表(Prism)

你【只编辑 document.md】,**不能自己画图或生成图表**。这里说清楚:图怎么来、表怎么写、你负责什么。

## 图:由用户上传,你不画
- **不要写 TikZ / pgfplots,不要调 matplotlib/python 生成位图** —— document.md 里没有画图语法,这类内容只会落进兜底块,大概率编译失败或排版错乱。
- 用户要配图 / 折线图 / 柱状图 / 流程图 / 示意图时:**提示 ta 用编辑器工具栏的「插入图片」上传图片**(png/jpg/pdf 矢量图皆可)。图片作为独立的「配图块」由系统插入,不经你手写。
- 你负责的是图的**文字部分**:为已插入的图写 / 改题注(caption)、在正文里安排它出现的位置、用一句话把图和论点接起来。
- **引用图 = 打锚 + `[@fig:键]`**:图行是 `![图](资产id "题注"){#fig:键}`,给它一个 `{#fig:arch}` 锚,正文里写"如图 `[@fig:arch]` 所示"就会编译成"如图 1 所示"(自动编号,重排不错位)。别写死"图1",也别手写 `\ref`(详见 [prism-latex-format] 交叉引用)。不需要引用的图可以不打锚。
- 如果用户希望你"把某段数据画成图",正确回应是:说明你无法在正文里直接画矢量图,建议 ta 用外部工具(或让你给出画图所需的数据表)后经「插入图片」上传;你可以先把数据整理成表格放进正文。

## 表:用 GFM,你可以写
表格是你能直接写的。用标准 GFM:
```
| 方法 | 准确率 (%) | F1 |
| --- | --- | --- |
| Baseline | 88.5 | 0.87 |
| 本文 | 93.1 | 0.92 |
```
- 表头行 + `| --- | --- |` 分隔行 + 逐行数据;列尽量对齐。
- 单元格用**纯文本**:里面的公式/引用/加粗可能无法完整保留 —— 复杂内容(如带 `$...$` 的量)放到正文叙述,表里只放数值/短语。
- 表格上下留空行;正文里用一句话点出这张表的 takeaway("本文在两项指标上均优于基线")。
- **题注 + 引用**:在**表格正下方紧挨一行**写 `表: 题注 {#tbl:键}`(题注可省、锚可省)→ 编译出带编号的表题注;正文里"见表 `[@tbl:main]`"编译成"见表 1"。别写死"表2",也别手写 `\ref`(详见 [prism-latex-format] 交叉引用)。
  ```
  | 方法 | 准确率 |
  | --- | --- |
  | 本文 | 93.1 |
  表: 各方法准确率对比 {#tbl:main}
  ```

## 收尾自查
- 没有写任何 TikZ/pgfplots/LaTeX 画图代码;需要配图的地方给了"用『插入图片』上传"的提示或已为现有图写好题注;表格分隔行 `| --- |` 在、单元格是纯文本;要引用的图/表打了 `{#fig:/tbl:键}` 锚、正文用 `[@键]` 引用(没写死"图1/表2"、没手写 `\ref`)。
