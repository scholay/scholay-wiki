# 选题 / 找研究方向

目标:基于**真实文献证据**给出 2-3 个**具体、可行、有 gap** 的候选方向,而不是空泛建议。全程用 minicod 检索佐证,**绝不凭印象编造"这个没人做过"**。

## Step 0 · 先问清约束(缺了就先问,别猜)
- 学科 / 子方向;用户的基础与资源(数据?算力?实验条件?合作方?)
- 时间线(一篇课程论文 / 一年的项目 / 博士选题?)与目标层次(会议/期刊/毕设)
- 用户已有的模糊想法或偏好(有就从它出发做新颖性核验)

## Step 1 · 领域测绘(用工具,别背书)
- `search_papers` 拉该方向近 2-3 年的代表作与高被引(limit≤8,多角度换词)。
- 挑 1-2 篇枢纽论文,`get_paper_references`(往回看奠基)+ `get_paper_citations`(往前看最新进展),摸清脉络。
- `search_authors` → `get_author_papers` 找活跃团队在追什么。
- 归纳:这个方向**已解决什么、公认难点是什么、最近在往哪走**。

## Step 2 · 找 gap(候选方向的来源)
系统性地找这几类缺口,而不是拍脑袋:
- **未解决/悬而未决的问题**(综述里 "future work"、多篇提到但没人做)
- **矛盾结论**(两拨结果打架 → 值得厘清)
- **方法迁移**(A 领域的新方法还没用到 B 领域的问题上)
- **新数据 / 新场景 / 新约束**(新数据集、新硬件、新法规、跨语言/跨人群)
- **复现与稳健性缺口**(声称的效果没人独立验证 / 只在窄设定下成立)

## Step 3 · 新颖性核验(证伪,不是自证)
对每个候选想法,**主动去搜最接近的已有工作**(`search_papers` 用该想法的关键词 + 换 source)。
- 找得到高度重合的 → 诚实告诉用户"这个已有人做(附文献),但可以在 X 处做增量"。
- 找不到近邻 → 说明"在检索范围内未见直接工作,最接近的是 …",而不是断言"绝对没人做过"。

## Step 4 · 可行性 & 风险
每个方向标注:数据/资源是否够得着、周期是否匹配、需要的技能、主要风险(数据拿不到?效果可能不显著?竞争激烈?)。

## 产出格式
给 **2-3 个候选方向**,每个:
1. **一句话问题陈述**(可证伪、够具体)
2. **为什么是 gap**(附检索到的证据:哪些工作到此为止 / 哪里矛盾)
3. **最接近的现有工作**(作者+年份)+ 你的想法相对它的**增量**
4. **可行性 + 主要风险**
最后给一句**建议的下一步**(先读哪几篇 / 先做哪个小验证)。

## 红线
- gap 必须有检索证据支撑,不编。
- 不夸大新颖性;能查到近邻就如实说。
- 提醒用户:选题最终要结合导师/领域判断,这里给的是有依据的起点。
