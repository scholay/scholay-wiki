# 论文解读

帮用户读懂一篇(或几篇)论文——**扎根在真实材料上**,不靠标题脑补。

## 先拿到材料

- 用户从文献集「引用」的论文已物化到当前工作目录 `references/` 下(见 [library-reference] 技能:先 `Read references/INDEX.md`,再按需 `Read references/paper-<id>.md`(元数据+摘要)和 `references/ref-<id>.pdf`(PDF 全文,可原生解析))。
- 用户直接粘贴的文本/上传的 PDF,直接读。
- 只有元数据+摘要、没有全文时,**明确说明只基于摘要**,不要假装读过全文;`pdf_url`(OA 直链)确需正文可试 `WebFetch`(可能失败)。

## 解读一篇时讲清这几层

1. **它解决什么问题、为什么值得做**(动机 / 缺口)。
2. **核心方法/思路**——用一句话主张 + 关键机制;能画就画(见下方渲染)。
3. **关键结果**——最能支撑主张的证据(数据集、指标、对比对象、提升幅度),忠实引用文中数字,别四舍五入到失真。
4. **局限与边界**——作者自陈的 + 你读出的(样本/设定/未验证的假设)。给出时说清哪些是原文说的、哪些是你的判断。

## 解读图 / 表 / 公式

- **说清坐标轴/行列的含义、单位、对比维度**,再讲它想证明什么、是否真的证明了。
- 数字直接引原文,别编;看不清或原文没给的,就说「原文未给」。
- 公式用 `$...$` / `$$...$$`(KaTeX 渲染),逐项解释符号含义。

## 渲染(务必遵守 CLAUDE.md 的输出约定)

- 方法流程/架构/时序 → 直接内联 ` ```mermaid `(flowchart / sequenceDiagram 等);数据趋势 → `xychart-beta`;占比 → `pie`。
- 复杂示意图 Mermaid 画不了 → 内联 ` ```svg `。
- 对比多篇 → 用 GFM 表格(维度 × 论文)。
- **严禁**用 ASCII/制表符手画图,**严禁**为「怕不能渲染」而生成 HTML 文件——界面本就渲染,内联即可。

## 底线

- 以材料为准,分不清就说分不清;区分「原文结论」与「你的解读」。
- 引用具体出处(作者, 年份;有页码/图号更好),多篇时标清是哪一篇。
- 用户没要求「逐段翻译」时,讲重点、讲逻辑,不要整篇复述。
