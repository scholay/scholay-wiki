## summary
agentbridge 的模型路由是「方案A·tier 档位制」:FeatureSpec.DefaultTier(spec.go:201-206,值域 main|haiku|sonnet|opus)声明 feature 默认档;hub 建连时 sendInitialTier(hub.go:280-299)按「会话 pinned_tier(用户显式选,agent_sessions.pinned_tier 列,migration 0052)|| spec.DefaultTier」给 executor 发一次 set_runtime_config{tier} 帧,executor(agent/src/server/ws.ts:83-89)把它存到 ws.data.tier(per-WS-connection 状态),turnLoop(agent/src/turn/turnLoop.ts:58)每轮以 `modelOverride || resolveTier(tier)` 解析成具体 model id。白名单校验只有一处硬编码:hub.go:258-260 validTier(main/haiku/sonnet/opus 四值),被 sendInitialTier(读 DefaultTier 与 PinnedTier 时各校验一次)和 tierFromFrame(hub.go:263-275,解析浏览器 set_runtime_config 帧)复用;repository.SetPinnedTier(repository.go:167-174)本身不校验,靠 hub 侧 tierFromFrame 过滤。tier→具体 modelId 的映射真源是 agent_config 单行表的 4 个槽位(agentconfig/model.go:34-37 MainModel/HaikuModel/SonnetModel/OpusModel),admin 改后 PushConfig 推给 agent/executor。per-session 锁定机制分三层:(1) 连接级 —— hub 建连发一次 initial tier,注释铁律「绝不会话中途自动换模型」(spec.go:204),但这只约束 backend 不自动切;(2) 会话级持久 —— 浏览器发 set_runtime_config{tier} 时 hub readLoop(hub.go:836-847)先 SetPinnedTier 落库再原样转发,重连后 sendInitialTier 重发实现 stickiness;(3) 具体 modelId 覆盖 —— serverside peerreview 每轮发 set_runtime_config{providerId:null, modelId}(ws_serverside.go:156-164,modelId 来自 agent_config 的 HaikuModel/MainModel,peerreview/service.go:152-175),executor 的 modelOverride 优先于 tier。⚠️ 关键现状:前端目前没有任何地方发 tier 帧 —— claw 前端(ClawModelSelector.tsx:67,79 + socket.ts:42-56)发的是具体 modelId,该帧在 hub 的 set_runtime_config case 里 tierFromFrame 返回空(pinned_tier 不落库),但帧被原样转发 executor 且 executor 对 modelId 零校验(ws.ts:85 直接 trim 后存 modelOverride)→「用户选任意 modelId」的通道事实上已存在,持久化靠前端 localStorage 每次 WS onOpen 重发,backend 的 pinned_tier(A3)当前无前端消费者。usage 帧带 model id:message_complete per-call 行(各带 model)落账,对账补差行 model="(reconciled)"(bridge.go:185),经 recordAgentTokens(hooks.go:63-79)把 model 写进 llm_token_usage —— 计费链已是 per-call model 粒度,天然不依赖 tier。配额钩子签名不含模型:PreUserMessageFn(ctx,userID,content)(spec.go:55)与 BudgetProviderFn(ctx,userID)(spec.go:60)都拿不到本会话 tier/model,现行日额度与预算是「不分模型」的单一池。

## designImplications
- 白名单收口点单一但分散读:换任意 modelId 时必须替换 hub.go:258-260 validTier 为「模型目录合法性查询」(查目录表),同时改 tierFromFrame(hub.go:263-275)解析 modelId 字段;sendInitialTier(hub.go:280-299)与 readLoop case(hub.go:836-847)是仅有的两个调用面 —— 改动范围可控,风险在于校验必须改为带 DB/缓存查询(现为纯内存四值比较,处于 WS 热路径,需加进程内缓存)
- 安全缺口现成:浏览器 set_runtime_config{modelId} 今天就被 hub 原样转发且 executor 零校验(ws.ts:85)——「用户选模型+7天限额」上线后这是绕过限额/选未授权模型的直接通道,重构必须在 hub.go:836-847 对 modelId 做目录∩用户授权校验(拒绝不合法帧,不能只是不落库继续转发),并考虑 executor 侧同样加白名单(纵深)
- pinned_tier 列复用受限:varchar(16) 装不下真实 model id(如 claude-sonnet-4-5-20250929),需新迁移加 pinned_model varchar(200) 或扩列;老数据(main/haiku 等档位值)需迁移映射或由 sendInitialTier 兼容读(validTier 老值→查目录转译);SetPinnedTier(repository.go:167-174)签名可沿用
- 模型目录化动的是 agentconfig 整套:agent_config 单行 4 槽位(model.go:34-37)→ 多行目录表意味着 repository.go:55-57 的 Updates、service.go PushConfig 载荷、agent/client.go 的 providers 推送格式、executor 的 providers.models 结构(agent/src/config/models.ts)与 /api/models 端点、claw/handler.go:196-217 ListModels(现在透传 agent,应改为 backend 目录直出)全部连带;peerreview fastModel/mainModel(service.go:152-175)也要改从目录取「任务用途→模型」映射
- 固定能力绑定(能力随模型)与现架构冲突点:能力轴(AllowBash/DisallowedTools/specDeny)是 per-feature 编译期静态,且通过三处同步生效(CreateSession --disallowed-tools、seed_history disallowedTools、hub 权限裁决 specDeny)——绑定到模型需把 denylist 变成「spec 静态 ∪ 模型能力」动态计算,并注意 executor seed only-if-empty 语义(ws.ts:116-118):会话中途换模型不会重推能力面,这反而与「会话锁定模型+固定能力」自然吻合 —— 建议把模型选择收敛到「建会话时刻」,禁止会话中途换模型(把 hub readLoop 的 set_runtime_config 转发直接砍掉,锁定只由 sendInitial 发)
- 7天限额的接入点:现行配额全在 PreUserMessage(vip 日额度)与 BudgetProvider(日内有界透支),两个签名(spec.go:55,60)都不含模型 —— 若限额按模型分池(不同模型不同 7 天额度),需给两个 Fn 加 modelId 参数并由 hub 在调用处(hub.go:910-923/995-999)传入本会话 effective model;若 7 天限额是全局单池则只改 vip 侧滑窗口径,agentbridge 零改动;计费数据已按 per-call model 落 llm_token_usage,7 天分模型统计的数据基础已具备
- 计费链无需大改是最大利好:accrueTurnUsage→recordAgentTokens 已经 per-call model 粒度记账,tier 概念在计费链中不存在;唯二盲点:serverside 整轮兜底行 model 为空(ws_serverside.go:301-313)、对账补差行 model="(reconciled)"(bridge.go:185)——若「7天限额按模型计」要以账本回溯,这两类行无法归到具体模型,需接受误差或在 executor 保证 calls[] 恒完整
- 会话锁定语义要重新声明:现状「锁定」= backend 不自动切 + 前端重连重发,并非强制;用户选模型持久化目前是前端 localStorage(claw)而非 backend ——重构应把真源统一到 agent_sessions.pinned_model(建会话时写死),sendInitialTier 改发 modelId(executor modelOverride 通道已支持,老 executor 兼容),并删除 localStorage 旁路,否则两个真源打架
- executor 内部带外调用仍依赖 tier:title-gen/记忆抽取固定 resolveTier("haiku")(completion.ts:14)——彻底去 tier 需给目录加「系统快模型」标记供 executor 内部调用解析;若保留 tier 仅作内部系统用途、对用户面全换 modelId,则 models.ts 的 Tier 类型与 resolveTier 可保留不动
- peerreview 不受用户选模型影响:DefaultTier 为空、不走 hub sendInitialTier、per-round modelId 自管(ws_serverside.go:156-164)——重构时只需把它的模型来源从 agent_config 槽位换成目录的「任务档位」映射,与用户选模型体系隔离
