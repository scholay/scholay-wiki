## designImplications
- 单行表假设根深蒂固:Repository.GetConfig 用 db.First、MarkPushSuccess/Failed 用 Where("1=1") 全表 UPDATE(repository.go:67,80)——改成「模型目录」多行表意味着 repo/service/handler 全部重写或另起新表(如 agent_model_catalog),不能在 agent_config 上直接扩行,否则现有推送/状态写回全被打散
- agent 端 provider 协议按「一个 provider = 一个 base_url+api_key+4 槽位映射」设计(scholay-managed 单 provider upsert+activate,client.go:941-987):若用户可选模型超出 main/haiku/sonnet/opus 四槽,要么每模型建一个 provider(activate 语义是全局唯一切活,冲突)、要么继续单 provider 但把「用户选模型」翻译成 per-round modelId(ws_serverside 已有此机制)或 tier;后者是改动最小的路径:目录条目 → 绑定到某槽位/具体 modelId,连接层复用 set_runtime_config
- 已有两条现成的模型选择通道可复用:交互式=tier(set_runtime_config{tier},整连接锁定+pinned_tier 持久化)、serverside=modelId(set_runtime_config{modelId} per-round);「用户选模型」若映射为 modelId 而非 tier,需注意 hub.go:836 目前只认 tier 帧、pinned_tier 只存 tier 值域——要么扩 agent_sessions.pinned_tier 语义(存 modelId),要么在目录里给每个模型标 tier 槽位;并注意「铁律:绝不会话中途自动换模型」(spec.go:204)——用户主动换是允许的,自动换不允许
- 「固定能力绑定」有先例可抄:FeatureSpec.DefaultTier 是纯代码声明(A1 刻意不入库,0052 迁移注释明说),per-feature 能力绑定同样可走 FeatureSpec 新字段;但如果要 admin 可配 per-feature/per-model,则需新表+新 admin API,不要塞进 agent_config 单行
- 7 天限额与现有配额体系的关系:现行配额是 vip tier-aware 日额度(agentbridge.StandardHooks→vip.Service.CheckDailyQuota,PreUserMessage 钩子),7 天窗口限额是新维度——挂钩点应仍是 FeatureSpec.PreUserMessage(交互)+ peerreview Submit(serverside),但计数窗口/粒度(per-model?per-user?)需要新存储;不要复用 stranded 的 usage_quotas 表(CLAUDE.md 明令新功能勿依赖)
- api_key 遮罩机制是 per-字段精确比对(handler.go:55 与 MaskSensitiveData 输出比对):模型目录若每条目带独立 api_key,遮罩=保留旧值的判定逻辑要逐条目复制,且 admin GET ?show_sensitive=true 的明文透出面会随条目数放大
- 推送时序有竞态防护先例:executor 可能晚于 backend 起(bootstrap.go:170 注释),现方案=启动 SyncOnce+8s 补发+60s 周期重推;模型目录若也要推到 agent/executor,需沿用该自愈模式,且 push_status 单行三字段无法表达「N 个目录条目各自推送状态」——要么目录只存 backend 侧不推送(agent 只认 provider 四槽+modelId 覆盖,目录纯粹是 backend 的选单),要么状态字段 per-row
- 最省事的架构方向(与现状最兼容):agent_config 保持单 provider(base_url/api_key/四槽位)不动;新增模型目录表(每行=展示名/modelId/绑定 tier 槽位或裸 modelId/能力标签/7天限额参数/enabled);用户选择持久化沿 pinned_tier 模式(agent_sessions 加列或新表);运行时下发复用 set_runtime_config 两通道——这样 PushConfig 链路完全不用改
- 新迁移编号从 0063 开始(0061/0062 已被未提交的 skill market 占用);建表用 CREATE TABLE IF NOT EXISTS + utf8mb4,遵循 fields/indexes/defaults 三段命名
