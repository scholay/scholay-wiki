## summary
agent 容器的模型选择是「单活跃 provider + 固定 4 槽位(main/haiku/sonnet/opus)+ 连接级 tier/modelOverride」三层结构。完整数据流:(1) admin 改 backend DB agent_config 单行(MainModel/HaikuModel/SonnetModel/OpusModel 四列)→ backend agent.Client.PushConfig(backend/internal/agent/client.go:919)把四列映射成 ModelMapping{main,haiku,sonnet,opus}(client.go:947-952),经 GET /api/providers 找 name="scholay-managed" → PUT 或 POST /api/providers → POST /api/providers/:id/activate(client.go:941-988)。(2) agent 的 http.ts 处理这些端点(agent/src/server/http.ts:101-153),normalizeModels(http.ts:284-293)把缺失槽位回退到 main,写入内存 providerStore(agent/src/config/providerStore.ts:78-105),并轻量持久化到 /home/bun/.executor/providers.json(providerStore.ts:39-63,无 schema 版本校验;真源仍是 backend DB,重启由 backend 重推);invalidateClient 使 Anthropic client 缓存失效(http.ts:121/141/151)。(3) WS 连接建立时 ws.data 默认 tier="main"、modelOverride=null(agent/src/index.ts:41);backend hub 建连后发一次 set_runtime_config{tier=会话 pinned_tier || spec.DefaultTier}(backend/internal/agentbridge/hub.go:277-299,「整连接锁定,绝不中途自动换模型」);浏览器/peerreview 也可发 set_runtime_config:agent ws.ts:83-89 解析——modelId(任意非空字符串,零校验,trim 后设 ws.data.modelOverride)和 tier(白名单 ["main","haiku","sonnet","opus"] 才生效);前端 claw 还发 providerId 字段(frontend-user/src/features/claw/api/types.ts:79)但 agent 侧完全忽略。(4) user_message → handleUserMessage 组 TurnInput{tier, modelOverride}(ws.ts:230-244)→ runTurn 决议 model = (modelOverride && trim) || resolveTier(tier)(agent/src/turn/turnLoop.ts:58),resolveTier = getActive().models[tier] || models.main(agent/src/config/models.ts:9-13)→ client.messages.stream({model,...})(turnLoop.ts:148-151),client 从活跃 provider 的 baseUrl+apiKey 构造(agent/src/anthropic/client.ts:15-24)。(5) out-of-band 单发(标题生成 title.ts、记忆抽取 extract_memory 帧 ws.ts:124-143)统一走 fastCompletion,模型硬编码 resolveTier("haiku") || resolveTier("main")(agent/src/turn/completion.ts:14),不受会话 tier/modelOverride 影响;usage 分别以 kind=title_gen(ws.ts:262)/ kind=memory_extract(ws.ts:135)回传。(6) 每个 LLM call 的实际 model id 已写进 CallUsage 随 message_complete.calls[]/usage/session_total 回传给 Go 计费链(turnLoop.ts:189、230-239)。set_runtime_config 字段全集(agent 侧认的):modelId(string,非空即覆盖,无值域校验,且一旦设定无法清除——ws.ts:85 只在非空时赋值,没有清空分支)、tier(4 值白名单);providerId 被发送但被忽略。modelOverride 恒优先于 tier(turnLoop.ts:58)且 agent 不持久(重连重置),tier 的粘性靠 backend pinned_tier(hub.go:836-843 持久化 + sendInitialTier 重发),modelId 的粘性靠前端每次 onOpen 重发(frontend-user/src/features/claw/api/socket.ts:44-51)。backend hub 对浏览器 set_runtime_config 帧原样转发(hub.go:844),即浏览器可注入任意 modelId 字符串直达上游 API。taskBudget 只是有界透支预算(软披露+硬 wind-down),与模型选择无关(turnLoop.ts:32-42、132-145)。/api/models 端点(http.ts:155-157)由 listModels 硬编码返回 4 个 tier 别名(models.ts:16-32),claw 后端透传给前端下拉(backend/internal/claw/handler.go:196-217)。

## keyFacts
- 槽位定义:ModelSlots 固定 4 字段 {main,haiku,sonnet,opus}(agent/src/config/providerStore.ts:10-15);Tier 联合类型 4 值(agent/src/config/models.ts:7)
- resolveTier:活跃 provider 的 models[tier],缺槽回退 models.main,无 provider 返回 null(agent/src/config/models.ts:9-13)
- listModels 硬编码 4 项 tier 别名数组 + provider 信息,供 /api/models(agent/src/config/models.ts:16-32;agent/src/server/http.ts:155-157)
- provider 配置注入点:POST/PUT /api/providers + POST /api/providers/:id/activate(agent/src/server/http.ts:101-153);normalizeModels 缺槽位回退 main(http.ts:284-293);GET /api/providers 脱敏 apiKey(http.ts:103-105)
- 持久化:providerStore 内存 + 尽力写 /home/bun/.executor/providers.json,loadOnInit 无版本校验(agent/src/config/providerStore.ts:39-63);真源=backend agent_config 表,重启由 PushConfig 重推
- backend 推送:PushConfig 把 agent_config 四列(MainModel/HaikuModel/SonnetModel/OpusModel)映射成 ModelMapping 推给 agent(backend/internal/agent/client.go:919-988,槽位映射在 947-952;ModelMapping 定义 56-61)
- 实际 model 决议:model = (input.modelOverride && trim) || resolveTier(input.tier),modelOverride 恒优先(agent/src/turn/turnLoop.ts:58);无 model → error code=config(turnLoop.ts:59-62);API 调用 client.messages.stream({model,...})(turnLoop.ts:148-151)
- Anthropic client 工厂只从 getActive() 单活跃 provider 构造(baseUrl+authToken),按 id/baseUrl/token 缓存(agent/src/anthropic/client.ts:15-24)——一次 turn 一个 client,不支持跨 provider 混用
- set_runtime_config 帧解析(agent 侧字段全集):modelId(string 非空即设 modelOverride,零值域校验,无清空分支)+ tier(白名单 ["main","haiku","sonnet","opus"])(agent/src/server/ws.ts:83-89);前端还发 providerId 但 agent 忽略(frontend-user/src/features/claw/api/types.ts:79)
- WS 连接初始:tier="main"、modelOverride=null(agent/src/index.ts:41);modelOverride 不持久,重连即重置
- backend 建连即发 set_runtime_config{tier = pinned_tier || spec.DefaultTier}(backend/internal/agentbridge/hub.go:277-299);浏览器发 tier 帧时 backend 持久化 pinned_tier 并原样转发帧(hub.go:836-847)——modelId 字符串同样被原样转发,backend 不校验
- peerreview server-side 按轮发 set_runtime_config{providerId:null, modelId}(backend/internal/agentbridge/ws_serverside.go:157-162);claw 前端 onOpen 重发 per-session 模型偏好(frontend-user/src/features/claw/api/socket.ts:44-51)
- out-of-band 单发(标题/记忆抽取)模型硬编码 resolveTier("haiku") || resolveTier("main")(agent/src/turn/completion.ts:14);标题链路 agent/src/turn/title.ts:17 + ws.ts:258-269(kind=title_gen);记忆抽取 extract_memory 帧 ws.ts:124-143(kind=memory_extract,Go 侧 SkipQuota)
- 计费维度已含 model:每个 LLM call 的 model id 写进 CallUsage(agent/src/turn/turnLoop.ts:189、230-239),message_complete 带 usage(本轮合计)+calls[]+session_total(ws.ts:172-186)——按模型计量的原始数据链已存在
- TurnInput 契约:tier: Tier + modelOverride?: string(agent/src/turn/types.ts:12-17);shadow turn 也带 tier?: Tier 默认 main(agent/src/server/shadowTurn.ts:27、99)
- taskBudget 与模型无关:只是单轮有界透支预算的软披露+硬 wind-down(agent/src/turn/turnLoop.ts:32-42、132-145)
- 能力面与模型解耦:工具面由 disallowedTools/allowBash/addDirs 决定,在 CreateSession/seed_history 设定、轮中不变(agent/src/server/sessions.ts:95-117;ws.ts:236-241 组装),当前不存在任何 model↔能力联动逻辑

## designImplications
- 4 槽位→N 模型目录的 agent 侧改动点清单:providerStore.ts:10-15(ModelSlots 结构→map/数组)、models.ts:7(Tier 联合类型)、models.ts:9-13(resolveTier 固定键+main 回退)、models.ts:16-32(listModels 硬编码 4 项)、http.ts:284-293(normalizeModels 硬编码 4 键)、http.ts:118/137(POST/PUT 走 normalizeModels)、ws.ts:87(tier 白名单数组)、ws.ts:33+index.ts:41(WSData.tier 类型与默认值)、types.ts:16(TurnInput.tier)、turnLoop.ts:58(决议表达式)、completion.ts:14(fast 模型固定 haiku)、shadowTurn.ts:27/99(tier 默认);backend 侧需同步:client.go:56-61/947-952(ModelMapping)、hub.go:258-275(validTier/tierFromFrame)、hub.go:277-299(sendInitialTier)、agent_config 表 4 列、claw handler.go:196-217(ListModels 透传)
- 复用 modelId 通道最省事:「用户选模型」的现成通道就是 set_runtime_config{modelId}→modelOverride→turnLoop.ts:58(claw 已在用);目录化可保留该通道,tier 通道退化为兼容层。但 agent ws.ts:85 对 modelId 零校验、backend hub.go:844 原样转发浏览器帧——引入按模型计价/限额/能力分档后,必须在 backend(权威侧)校验 modelId ∈ 目录且用户有权使用,否则用户可用 devtools 发任意上游 model id 绕过目录/限额/能力绑定
- 模型选择必须移到 backend 持久:modelOverride 在 agent 不落盘、重连即清(index.ts:41),现在靠前端 onOpen 重发(socket.ts:44-51)——不可信且多端不同步。应仿照 pinned_tier 机制(hub.go:836-843 持久化 + sendInitialTier 建连下发)扩展为 pinned_model,由 backend 在建连时权威下发
- modelOverride 无清除语义是坑:ws.ts:85 只在非空时赋值,发 tier 帧不清 override 且 override 恒优先(turnLoop.ts:58)——用户「切回默认」需要新协议语义(如 modelId:"" 显式清空),重构时必须定义
- 「固定能力绑定」是全新改动面:当前工具面(disallowedTools/allowBash/addDirs)与模型完全解耦,且轮中不可变(sessions.ts 只在 CreateSession/seed_history 设)。模型↔能力绑定需在 ws.ts:230-244 组 TurnInput 处按当前 model 叠加额外 denylist,或由 backend 在下发 pinned_model 时同步下发能力面;注意 executor 侧约定是「只会更严、绝不拓宽」(types.ts:18)
- 目录若跨 provider(不同 baseUrl/apiKey)是大改:现架构单活跃 provider(providerStore.ts:69-72 getActive 单值),client 工厂只认活跃者(anthropic/client.ts:15-24),一次 turn 一个 client。目录限定在单一活跃 provider 内(同 baseUrl 下 N 个 model id)则改动小得多——建议第一期锁定单 provider
- out-of-band 系统调用(标题/记忆)不应跟随用户选择:completion.ts:14 固定 haiku→main;目录化后失去 haiku 概念,需在目录里为模型打 role 标(如 fast/cheap)或在 agent_config 保留一个「系统任务模型」指针;7 天限额计量时注意这两类已带 kind 标(title_gen 正常计费、memory_extract SkipQuota),口径要延续
- 7 天限额的数据基础已具备:每 LLM call 的 model id 随 CallUsage/calls[]/session_total 回传(turnLoop.ts:189/230-239,ws.ts:172-186),backend 计费链(accrueTurnUsage/vip)按 model 维度聚合即可,agent 侧无需为限额改动;但现有配额闸是 PreUserMessage 前置钩子+taskBudget 单轮透支,按模型分档限额需在 backend 钩子里引入 model 维度(用户当前 pinned_model)
- providers.json 兼容:providerStore.ts:50-63 loadOnInit 无版本/schema 校验,改 models 结构后旧文件会以错误 shape 载入;需加版本字段或容忍首启窗口(resolveTier 返 null→turnLoop.ts:59-62 已有 config 错误兜底,backend 重推即恢复)
- 迁移顺序建议:先改 agent 数据结构(models 目录 + 校验 + 清除语义)保持 4 槽位兼容读法,再改 backend agent_config(4 列→目录表)与 PushConfig,最后动前端选择器与 pinned_model 持久化——每步 /api/models 契约都要同步(claw handler.go:202-215 有按 id 去重逻辑,目录化后该去重应移除)
