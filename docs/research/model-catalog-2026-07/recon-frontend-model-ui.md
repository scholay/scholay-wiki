## designImplications
- 「模型目录」与现状是根本性数据源变更:现在前端拿到的 models = admin 4 槽位去重(常常只有 2 条),id/name/description 都是 tier 语义。目录化后需要新的后端目录接口 + 新 DTO(展示名/描述/能力标签/限额信息),前端 ClawModelInfo(session.ts:379-383)与 useClawModels 要整体替换;若三 feature 共用目录,该 hook 应上提为 shared/api/models.ts(claw 私有 api 不允许被其他 feature import,依赖方向铁律)
- 选择状态必须从 localStorage 迁到服务端:现状 per-session 选择只存本机浏览器(session.ts:417-421 明确『不放 backend』的前提是无计费含义)。一旦绑定 7 天限额,后端必须权威知道每轮用的是哪个模型 —— 而现在 agentbridge 对 set_runtime_config 无解析透传(ws.go:395-409 只认 user_message),后端对『用户切了模型』完全盲。可行路径:a) 后端解析并落库 set_runtime_config(校验 modelId ∈ 目录、记到 agent_sessions 或新表);或 b) 改成模型随 user_message 帧携带/HTTP 落库,WS 帧退化为运行时通知。任一方案下前端 socket.ts:42-57 的『每次重连重发 localStorage 偏好』逻辑都要改成从服务端状态恢复
- 7 天限额的拦截点与信号:后端 PreUserMessage 配额钩子(StandardHooks→vip 日额度)是现成挂点,但需要拿到本轮模型才能按 per-model 窗口计;前端已有 quota_exceeded 信号链(useAgentSocket.ts:300-309 + quota-events + 回滚 pendingTurn),per-model 限额需要可区分的错误 payload(哪个模型、何时重置)并在选择器里展示剩余额度/置灰超额模型 —— AgentErrorFrame 处理与 quota-toast 都要扩展
- Cursor 式选择器进 composer 的接法已就绪:Composer.tsx leftActions 插槽(:63,渲染于 :191-192)即落点。建议新建业务无关的 shared/components/chat/ModelSelectorButton.tsx(下拉+打勾+额度徽标的纯壳),各 feature 在自己的包装层喂数据:ChatComposer.tsx:316、SmartComposer.tsx:95、PrismChatPanel.tsx:154 三处各加一个按钮;claw 需同时从 ClawSidebar.tsx:46-49 摘除旧 ClawModelSelector(或保留双入口但状态单源)
- smart-search / prism 接入成本 = 类型 + UI,管道零改:browserFrameForwardable(ws.go:479-486)本就放行 set_runtime_config,只需给 features/search/api/smart-search.ts:36-39 与 features/prism/api/ws-types.ts:13-18 的 ClientMessage 加 set_runtime_config arm,并在各自 socket 包装(prism/api/socket.ts、search/api/smart-search.ts:353)加 onOpen 重发逻辑(可把 claw socket.ts 的 onOpen 模式抽成 shared 工具);注意若『固定能力绑定』意味着某 feature 锁定某模型,则后端应在桥上按 feature 白名单校验 modelId,而不是信任前端不发
- admin 端是重写不是扩展:AgentConfigPage 的 4 槽位表单(:120-157)服务的是 agent 内核 tier 路由(标题/记忆抽取用 haiku 槽),目录化后仍需保留槽位配置(agent 内部任务),另起「模型目录管理」页(CRUD 表格:模型 id/展示名/能力绑定/7 天限额/上下架),新建 features/admin/api/model-catalog.ts + pages/ModelCatalogPage.tsx + admin nav/routes 注册;两套配置的关系(目录条目是否必须映射到某 provider 槽位)是核心设计决策 —— agent 侧 ws.ts:83-89 接受任意 modelId,故目录模型只要上游网关认就无需改 agent
- 现存漂移要一并清:friendlyDesc(ClawModelSelector.tsx:174-189)硬编码英文 description 已失配,目录化后展示名/描述应完全由后端目录下发,删除前端映射;ContextMeter(:30)与历史条目的 model 字符串也应经目录映射成展示名
- 移动端与新对话语义:移动 claw 无任何模型 UI,需新增入口;『新对话先选模型再建 session』的两段式记忆(new-conversation pref + transferNewConversationModel,session.ts:473-499、useClawConversation.ts:374,438)在服务端化后要重新设计 —— 例如建 session 请求直接带 modelId,消灭 localStorage 中转
- providerId 字段现状恒为 null(ClawModelSelector.tsx:67,79):帧协议里预留了 provider 维度但从未用;目录化若引入多 provider,该字段可承接,但后端/agent 的多 provider 支持(agent getActive 单活跃 provider)是更大的前置工程
