## designImplications
- model id 在链路每一跳都可得,唯一丢失点是 UsageObserver 签名(llmusage/service.go:50 只传 userID+totalTokens):按模型单价加权的最小侵入改法有两种——A)扩 observer 契约为 func(u Usage) 或 (userID, model, 四类拆分),bootstrap 闭包(bootstrap.go:389-391)里查模型目录单价加权后再 vip.AddUsage;B)在 Record 内部先按 u.Model 算出 weighted 值再喂现 observer(签名不动)。两者都要求「模型目录」提供 per-model 费率查询(当前系统无任何单价存放点)
- 加权应按四类 token 分别计价(input/output/cache_read/cache_creation 单价差一个量级),而现 observer 只拿 total(四项裸加,service.go:81-83)——若只对 total 乘一个模型系数,cache_read 重的功能(prism/审稿)会被系统性高估;Usage 里四类齐全,拆分在 Record/observer 一跳即可拿到,不需要动 agent 协议
- 扣减语义改动集中三处:1)llmusage/service.go:91-93 observer 触发点(或签名);2)bootstrap.go:389-391 接线闭包(注入模型单价表);3)vip/quota.go AddUsage/CheckDailyQuota/RemainingBudget 的「单位」——Redis 计数器从 raw token 变成加权 token(或抽象的「点数」),DailyCeiling 配置值、超额文案 quotaExceededMessage、前端余量展示必须同步换口径
- SS#2 预算盖章链(hub.go:992-999 stampBudget → agent turnLoop.ts:119-137 用 raw calls 合计自配速)与加权口径会错位:要么后端把加权余量按「当前会话模型费率」反折算成 raw token 再盖章,要么把费率表随 PushConfig 下发给 agent 让它按加权算 spent——「用户选模型+固定能力绑定」重构里每会话模型固定,反折算是最小改动且天然贴合
- accrueTurnUsage 的补差行 model="(reconciled)"(bridge.go:185-195)没有真实模型:加权计费需定价兜底策略(建议按该会话绑定模型计价——模型目录化后每 session 有确定 model,兜底反而变简单);同理 peerreview 整轮兜底 chatUsageToAgentUsage model 留空(ws_serverside.go:303)
- 账本表建议加成本快照列(unit_price_version/weighted_tokens 或 cost)而非读时现算:模型单价会调价,读时 join 目录表算历史成本会漂;新增迁移遵循幂等规范(add_column_if_not_exists),admin 聚合(repository_admin.go 各 SUM)加一列 SUM 即可让看板出「成本/加权消耗」视图——ByModel/DailyByModel 聚合已存在,前端改动小
- 「用户选模型」落地后 model 真源变化:目前 agent 侧 model 由 agent_config 单行表全局决定(turnLoop.ts:57-58 modelOverride 或 resolveTier),per-call model 是事后记账;重构成 per-session 选模型后,记账链不用改(model 仍随 per-call 帧回传),但配额预检 CheckDailyQuota(quota.go:205)目前对「将要用哪个模型」无感——若不同模型扣不同额度,预检/预算盖章需要知道 session 绑定的模型费率,建议把费率解析放在 FeatureBridge 侧(session→model→rate)而非 vip 内部,保持 vip 只认「点数」
- SkipQuota 语义天然兼容加权(memory 抽取等系统开销仍只记账不扣点),无需改;OnMessageComplete slog 钩子与计费无关,别在那里加扣减(会与带内帧双计,hooks.go:36-37 已有明确警告)
- 「7 天限额」与现单日窗口不兼容:tokenDayKey 按自然日换 key(quota.go:96-97、25h 过期 :294-297),7 天滑窗需改成 7 个日 key MGET 求和(过期改 8 天)或独立滑窗结构;tokenWindowUsed 的「手动重置基线」语义(quota.go:192-197)在多日窗口下要重新定义(重置是清 7 天还是清当日)
- 若未来切 journal 权威计费(P0 影子 agent_billing_ledger),该表缺 model 列(journal_model.go:64-77),迁移时需一并补 per-call 粒度或 model 列——现在设计模型目录时把「费率快照」概念预留进去可少走一次表结构返工
