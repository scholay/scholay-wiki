# Scholar Platform — Frontend↔Backend Architecture & Data-Exchange Review

> **Method & coverage.** 8 cross-cutting dimensions of the FE↔BE seam (REST contract/type-drift, error-code contract, agent-WS protocol, auth/secret boundary, data-exchange round-trips, cache/state coherence, feature-module symmetry, SSR/public/anon contract), each mapped against real code and then **adversarially verified** finding-by-finding (refuted claims dropped, `uncertain` kept and labeled). Performance was out of scope (analyzed separately). The auth/secret-boundary and cache/state-coherence dimensions were re-run as a backfill pass; their results are folded into Theme 7, the findings tables, and the "preserve" list. Generated 2026-06-26.

## Executive Summary

The Scholar FE↔BE seam is a tale of two halves. The **transport layer is genuinely well-built**: a uniform `{code,message,data,request_id}` HTTP envelope ([response.go:17-22](backend/internal/common/utils/response.go)) consumed through one axios instance and one `toApiError` normalizer ([http.ts:115](frontend-user/src/shared/lib/http.ts)); a centralized, redacting friendly-error discipline (`SafeError`/`isInfraError`); a clean public-vs-authed redaction contract (promo `PublicView`, masked turnstile secret, OAuth login-urls expose only `client_id`+CSRF state); and a mature, declarative **agent-bridge backend spine** (`FeatureSpec` + `StandardHooks` + a startup `VIPCheckerWired` self-check) where a new read-only agent feature really is "a spec + a thin handler." But the **shape of the data inside the envelope is governed entirely by hand, with no machine-checked link between the Go DTOs and the ~330 TypeScript interfaces that mirror them.** The single biggest architectural risk is therefore **silent contract drift on a dead single-source-of-truth promise**: the project's own `CLAUDE.md` mandates types be generated from `schema.d.ts` via `gen:api`, but `gen:api` points at a `swagger.json` that no longer exists, `schema.d.ts` is absent, and the entire network layer hand-mirrors the backend — exactly the anti-pattern the docs ban. Every backend field rename or `gin.H` key change drifts silently to `undefined` at runtime with zero build-time or request-time signal. This root cause radiates into four colliding JSON casing regimes, a quadruplicated agent-WS frame contract, and a business-critical quota signal that is type-invisible to every feature and works only through `as`-casts.

Crucially, the weakness is **localized to data-shape governance, not to the control planes**. The two highest-stakes cross-cutting concerns — the **auth/secret boundary** and **cache/state coherence** — were verified to be genuinely well-built (Theme 7): one single-source token, one unified `notifyAuthLost` funnel, ws-tickets with ownership checked at issuance, comprehensive centralized secret redaction (the prior-audit "thirdparty Create echoes plaintext api_key" is **fixed on this branch**), disciplined TanStack-Query invalidation, and the "agent history disappears on re-entry" bug class closed consistently across all three WS features. No secret reaches a non-admin caller; no mutation silently fails to invalidate. So this is not a system in trouble — it is a system whose transport, security, and state machinery are mature, with one un-closed discipline (the JSON contract itself) that the rest of the report drills into.

## System map

Three transports cross the FE↔BE boundary, all behind nginx same-origin, plus a fourth (SSR) that exists purely for crawlers.

```
                        ┌────────────────────────── nginx (same-origin) ──────────────────────────┐
                        │  $is_crawler (UA allowlist, nginx.conf:85-96)                            │
   Browser (SPA) ───────┤                                                                          │
   Crawler      ───┐    │  /api/*  ──────────────────────────────► backend:8080                    │
                   │    │  /  (human/JS) ─────────► frontend Vite shell (RouteSEO / react-helmet)   │
                   └────┼─►/{paper,journal,news,blog,...} (bot) ─► @ssr_backend ServeIndexHTML      │
                        └──────────────────────────────────────────────────────────────────────────┘

  (1) REST ENVELOPE                          (2) WS TRIANGLE (agent features)
  ───────────────                            ──────────────────────────────
  axios → {code,message,data,request_id}     FE POST /<feat>/session/ws-ticket  (30s GETDEL Redis ticket)
  toApiError → ApiError{status,code,msg}      │  → GET /messages + /context + GetOrCreateSession
  BizCode (hand-mirror of errcode/codes.go)   ▼
  FE unwrap: data.data (ad hoc per file)     FE  ──ws_token──► backend agentbridge/ws.go (transparent pipe)
                                                                       │  (injects error/displaced/resync)
  (4) SSR PATH (bots only)                                            ▼
  handler_ssr.go regex-rewrites              scholar_agent container  ◄── canonical frame schema lives HERE
  <title>/<meta>/<canonical> + noscript      (events.ts ServerMessage union)
  from 5 hand-maintained per-path lists

  AUTH FUNNEL: HTTP = JWT (UserAuth/AdminAuth middleware, role in token).
               WS   = one-time ws_token only (legacy ?token=<jwt> removed).
               Anon = X-Anon-Id header (axios) + anon_id body (keepalive), both from one getAnonId() uuid.

  (3) SSE PATH (peerreview only): event: snapshot/delta/done/error, (submissionID,slot) broker.
```

**Frame-schema authority is inverted from where the types live.** For the WS triangle the *true* protocol source is the agent container's TypeScript (`agent/src/server/ws/events.ts`); the backend is a near-transparent pipe that only normalizes away agent-internal frames (`token_usage`, `memory_update`, `permission_request` under auto-mode) and *injects* `error`/`displaced`/`resync_*`. That schema is then re-declared, by hand, in the backend's inline probe structs **and** three separate FE feature unions — four mirrors of one protocol, none generated.

The **good seams worth preserving**: the live-fold vs history-replay isomorphism (one shared `replayHistoryAsTurns` + `appendStreamMessage`, resync replays the live event stream so all three paths converge); the ws-ticket lifecycle (one-time GETDEL, feature-key binding, session/path mismatch check, no JWT-in-URL); content single-sourcing for blog/qa/resources (`content.go` go:embed feeds both SSR noscript and the public API); device routing (one `isPhoneDevice()` decision point that correctly returns false for bots and never redirects responsive/SEO pages); the per-page `Omit("raw_json")` and shared-queryKey journal-detail dedup that show the team is cost-conscious where it counts; the **auth funnel** (one `getAuthToken()` source read by every non-React caller, one `notifyAuthLost` sink with a de-dup latch, 403-not-401 for role mismatch so a valid login is never evicted); **ws-ticket ownership** (`OwnsSession`/`GetProject` checked *before* minting, GETDEL one-shot, feature-key bound); **centralized secret redaction** (`utils/secret.go` `PreserveSecretOnEmpty` applied to every config-read, all admin-gated); and **cache-invalidation discipline** (collected `library-invalidation`, `staleTime:0 + refetchOnMount:'always'` on all agent-history/list queries, optimistic updates that reconcile against server-returned objects).

## Cross-cutting themes

These themes recur across dimensions and are the real content of this review. Themes 1–6 are where the seam needs work; Theme 7 is the counterweight — the parts that are already closed and should be defended.

### Theme 1 — The dead single source of truth (root cause)
The most-cited finding in the dataset, surfaced independently by **six of eight dimensions** (d1, d2, d4, d5, d7, d8 — even the auth dimension flags it: `BizCode` is a hand-mirror with no generation guard, AUTH-05). `gen:api` → `openapi-typescript ../swagger.json` (package.json:16) targets a spec that was de-lined with Semantic Scholar; `swagger.json` and `schema.d.ts` both confirmed absent on disk. In their place: 91 hand-written api files, ~330 interface/type declarations, the only `@/shared/api/schema` reference a stale TODO comment ([admin/api/usage-logs.ts:7](frontend-user/src/features/admin/api/usage-logs.ts)). The project's `CLAUDE.md` simultaneously **mandates** the generated workflow and **bans** hand-mirroring — so the loudest convention is the one most thoroughly violated, and a new contributor will trust a workflow that cannot run. This is the enabler for **every** drift finding below: there is no compiler, no request-time validator, nothing diffing the two halves. The team has partially self-mitigated with an informal paired-file convention (28+ api files cite the Go struct path in comments), which is the right instinct but is unenforced.

> Evidence: d1-dead-generator-77-mirrors, d2-no-codegen-277-handwritten, d5-handwritten-contract-no-codegen, d7-no-generated-schema-72-handwritten-mirrors, d8 (multiple).

### Theme 2 — One logical event, many wire encodings (transport-split vocabularies)
The same business event has no canonical representation; its encoding is chosen per transport, then hand-detected per transport on the FE. **"Quota exhausted"** is the canonical example: numeric `6010` over HTTP (`errcode.AgentQuotaExceeded`, detected via `BizCode` in [http.ts:38](frontend-user/src/shared/lib/http.ts)), the magic literal `6010` over SSE (not even tied to `BizCode`, [sse-post.ts:86](frontend-user/src/shared/lib/sse-post.ts)), and the *string* `"quota_exceeded"` over WS ([ws.go:947](backend/internal/agentbridge/ws.go) → [useAgentSocket.ts:275](frontend-user/src/shared/hooks/useAgentSocket.ts)). Auth-loss fans out identically across three independent `notifyAuthLost` sites. The downstream sink is unified (`QUOTA_EXCEEDED_EVENT`), which limits blast radius, but the *trigger matching* is three literals in three files with nothing enforcing they agree. A rename in Go renumbers one, type-checks clean, and silently disables quota gating on whichever transport was missed.

> Evidence: d2-dual-error-taxonomy-http-vs-ws, d8-quota-three-wire-formats, d3-error-code-type-drift.

### Theme 3 — Shared abstraction, leaked through casts (the generic that hides the contract)
The FE agent stack is genuinely unified — all three WS features consume the shared `useAgentSocket`/`agent-stream`/`agent-history` (the `agent-ws-hook-unify` consolidation held). But the shared hook is generic over `<TServer extends AgentStreamMessage>`, and `AgentStreamMessage` is only `{type:string; text?:string}`. So the hook must **cast away its own type** to read every behavior-critical field: `(evt as {code?:string}).code === 'quota_exceeded'`, `(evt as {message?:string}).message`, `(evt as {content?:string}).content`. The single most business-critical discriminator in the system is read on a field **none of the three feature `ServerMessage` unions declare** (and the one that does — prism — never consumes it). The type system provides zero protection on exactly the path where billing UX would silently break. The good news, verified by the adversarial pass: this is a *single chokepoint* cast, not load-bearing across many sites, which is why it stays correct today.

> Evidence: d7-shared-hook-untyped-field-access, d3-error-code-type-drift, d1-ws-error-frame-untyped-fields.

### Theme 4 — Convention by sample, not by enforcement (drift between near-identical copies)
Repeatedly, a *correct* pattern exists but was never "收口" (closed off) into an enforced rule, so siblings drift. (a) **Casing**: snake_case structs dominate (vip/library/prism/news/user) but agent-bridge emits camelCase via ad-hoc `gin.H`, minicod mirrors upstream camelCase, and feedback is a fourth camelCase island — forcing the FE to hand-bridge `citationCount ↔ citation_count` for the *same paper* ([library/api/papers.ts](frontend-user/src/features/library/api/papers.ts)). (b) **Pagination**: six distinct list-response shapes (`{items,total}`, `{list,total,page,pageSize}`, `{users,...,page_size}`, `{items,has_more}`, `{total,offset,next,data}`, `{messages,totalTurns,hasMore}`) and a `pageSize` vs `page_size` request-param split with no shared helper. (c) **Envelope unwrap**: the one universal invariant (`{code,data}`) is re-decoded ad hoc per file — the *identical* `unwrap<T>` helper is copy-pasted into four files, and ~11 distinct `?? {}`/`?? null`/`?? raw` fallbacks coexist; a newly-added envelope field (`request_id`) is read by zero FE consumers. (d) **Bind-error redaction**: `SafeBadRequest` exists and works, but ~37 sites still echo raw `err.Error()` through non-Safe helpers.

> Evidence: d1-casing-three-regimes, d5-pagination-shape-and-param-drift, d7-response-envelope-unwrap-adhoc, d2-raw-binding-errors-echoed.

### Theme 5 — Aspirational contracts that no side runs (documentation that misleads)
Several contracts are richly *documented* on both sides but *executed* on neither — pure maintainer traps. `SessionTakenByOtherLogin` (2019) is defined in Go, HTTP-mapped to 409, and handled by FE `isSessionTakenError` — but **no backend handler emits it** (the kick always arrives as 2030) and `isSessionTakenError` has **zero call sites**; the documented "banner not redirect" UX runs nowhere. The `displaced.reason` frame declares a 4-value enum with per-code comments on both sides, but the backend hardcodes one value and the FE branches on none (it reads `message`, and the field literally named `displacedReason` is populated from `message`). Nine of thirteen `BizCode` constants are declared with documented UX (paywall on 4020, session-rebuild on 6020) that is never wired. These read as complete contracts and will mislead the next maintainer into assuming behavior that does not exist.

> Evidence: d2-session-taken-2019-dead-contract, d3-displaced-reason-phantom-contract, d2-bizcode-mostly-unconsumed, d3-resync-permission-replay-fold-tolerance.

### Theme 6 — Normalization that belongs on the backend, smeared across the FE
Where the backend under-delivers a clean shape, the FE backfills business logic — and the copies drift. The clearest case: `JournalsByNames`/`GetJournal` pass raw Minicod `json.RawMessage` (redacting only download URLs), so the upstream's idiosyncratic encoding (`fqb_major_quartile:"1 [1/118]"`, string `jcr_impact_factor`, `openalex_is_oa: 0/1`, warning-recency) is parsed and re-derived in **~five FE files with regex**, and they already disagree: desktop shows the 预警 chip only within a 2-year recency window, mobile shows it for any historical warning — two consumers reaching different conclusions about the same journal. The 158-and-counting `gin.H{}` inline response bodies (no Go struct, string-literal keys) are the same phenomenon at the envelope level: the FE interface is the *only* written half of the contract.

> Evidence: d5-journal-normalization-smeared-in-fe, d1-ginh-untyped-responses, d5-search-thin-enrich-waterfall-composable.

### Theme 7 — The seams that are already closed (auth, secrets, cache, ownership)
The counterweight, and it is substantial. The **auth/secret boundary** is "unusually disciplined": a single-source token (`auth-token.ts` — `localStorage.auth_token` canonical, store a cross-tab mirror, `scholay_token` cookie only for header-less `<img>`/iframe loads), every non-React caller reading `getAuthToken()` (closing the historical "axios 200 but SSE/WS 401" drift), one `notifyAuthLost` sink with a de-dup latch, and the deliberate **403-not-401 for role/type mismatch** so a valid login is never evicted ([http.ts:165-170](frontend-user/src/shared/lib/http.ts)). The WS-ticket migration is complete and **ownership is verified at issuance** (`OwnsSession` / `GetProject(projectID,userID)` *before* minting; GETDEL one-shot; feature-key bound; the old `IssueWSTicketTrusted` bypass retired and fails closed). **Secret redaction is comprehensive and centralized** on `utils/secret.go` (`PreserveSecretOnEmpty` treats both `""` and the mask sentinel as "unchanged") — every credential-bearing config-read masks, every such endpoint is admin-gated, and **no public or non-admin endpoint serializes a secret**; notably the prior-audit "thirdparty Create回吐明文 api_key" is **fixed on this branch**. The **cache/state seam** is equally clean on the discipline axis: queryKeys follow the `[feature,resource,...]` convention, mutations pair with correctly-scoped `invalidateQueries` (no silent-stale write found), the "history disappears on re-entry" bug class is closed *consistently* across smart-search/claw/prism (`staleTime:0 + refetchOnMount:'always'`, or prism's useEffect-direct fetch), cross-tab logout mirrors token *and* user via a storage-event listener, and the CLAUDE.md "no server data in zustand" ban is respected. The residual findings here are all low/info coupling smells, not defects — see AUTH-01/02, SC-1/2/3/4. **This is the discipline the rest of the report asks to extend to the data-shape layer.**

> Evidence: auth narrative (single-source token, unified funnel, ownership-checked ws-tickets, centralized redaction), cache narrative (invalidation discipline, closed history-bug class, cross-tab coherence), SC-5 (clean seam), and the refuted AUTH-03/AUTH-04 (claimed weaknesses that did not hold up).

## Prioritized recommendations

Ordered. The first three are quick contract-hardening wins; the last two are the structural refactors that pay down the root cause.

1. **Resolve the dead-codegen lie first (H1) — it is a decision, not a refactor.** Either restore a real spec and re-point `gen:api`, or delete the dead script + `CLAUDE.md` mandate and adopt the enforced paired-file convention. Until this is decided, every other drift finding is unbounded. Cheapest credible version: keep hand-mirroring but add a CI contract test that replays recorded BE responses against the FE types/zod, so drift fails the build instead of a user's screen.

2. **Kill the phantom and decorative contracts (M7, L7, I4, L9, plus 2019/2016/6020 dead codes).** Pure deletion + a few `as`-cast removals — including the vestigial `?token=` JWT-in-query branch (L9), which no caller uses and which reintroduces the exact log-exposure risk ws-tickets removed. Zero behavioral risk, immediate reduction in maintainer-misleading surface. Do this in the same pass as the codegen decision while the error vocabulary is fresh.

3. **Unify the quota/auth detection (Theme 2: M5 + L3 + d8 quota).** Centralize one FE predicate that accepts numeric `BizCode.AgentQuotaExceeded` *or* the WS string, replace the `6010` magic literal in sse-post.ts, and document the HTTP-code↔WS-string mapping in one referenced comment block. Small, high-leverage — it protects the single most business-critical signal.

4. **Collapse the agent-WS contract to one shared union (M4 + M5).** Export the agent `events.ts` consumed-subset as a build artifact, fold the three FE unions into `@/shared/types/agent-ws.ts` (with typed `code`/`retryable`), and centralize the backend probe structs into a named `frames.go`. This is the structural fix that makes Theme 3's cast-leak a compile error and stops the quadruplicated drift at its source.

5. **Standardize the envelope conventions (M1, M2, M3, L1, M6).** One wire casing (snake_case), one paginated envelope + request contract, `gin.H` → named structs on FE-critical paths, route public read endpoints through `utils.Success`, and push journal normalization into a backend DTO. These are larger but mechanical; sequence them behind a version bump and migrate the two `pageSize` param outliers and the agent session/context responses first (lowest blast radius, highest churn).

**What to preserve untouched (Theme 7):** the `utils.Response` envelope discipline and `SafeError`/`utils/secret.go` redaction (no secret reaches a non-admin caller); the `agentbridge.FeatureSpec`/`StandardHooks`/`VIPCheckerWired` backend spine; the ws-ticket lifecycle with ownership checked at issuance (one-time GETDEL, feature-key binding, no JWT-in-URL); the single-source token + unified `notifyAuthLost` funnel (403-not-401 so a valid login is never evicted); the TanStack-Query invalidation discipline and the closed "history disappears on re-entry" bug class (`staleTime:0 + refetchOnMount:'always'`); the live/resync/history fold isomorphism; content single-sourcing; and the `isPhoneDevice()`/SSR device-neutral SEO routing. These are the clean seams — and the **auth and cache layers are the model**: the work above is simply about extending that same "close the convention into an enforced rule" discipline to the data-shape parts of the boundary that grew up without it.
