## 〇 · 三句话

1. **卖的不是"能算"，是"算完到论文之间那 2–4 小时手工活" + "这段做对了我敢写进论文"。** 中文市场已把「已知方法 + 干净宽表 + 标准检验」打到 ¥9.8/天甚至 0 元（B3），而代做仍能收 ¥500–6000（B3 §四）——差价全在脏数据整理、方法有依据、交付物合规、返修责任这四件事上，而这四件恰好是算法目录型产品结构上装不下的。
2. **工程投入不该花在"让模型更懂统计"，而该花在把三件事夺权给确定性代码**：前提检验、报告里的数字来源、数据体检。StatQA 显示模型选方法已强于目标用户（64.83% vs 有统计背景者开卷 53.45%，但**人类基线仅 n=6，是弱证据**，B4 更正 #48）；BLADE 显示模型真正最弱的一维是**把概念落成具体统计模型**（精度 <35%，而概念变量选择反而有 60–70%，B4 更正 #45——原报告标签写反过，方向必须按更正版走）。
3. **不建 7000–9000 行的 StatEngine，也不上 Run 引擎。** 旧方案的"引擎算数 / LLM 问诊"核心裁决仍然对（C2 §2.1 被三份材料独立复证），但它的前置工程已过期一半（统计库已装齐、pip 通道已开），且 8 天 P0 不现实（C2 §2.2 实际 15–20 天）。P0 走"**守门 + 报告确定性，计算层受控自由**"的窄版引擎（**~2400 行 pip 包**——本次修订从 ~1500 上调，因为原稿漏掉了 bundle schema / 15 条决策表 / 模板矩阵这三块，见 §4.1.1–4.1.3），把省下的预算花在**上传通道接线**和**第四份 hook 克隆债的收敛**上。

|---|---|---|
| **智能搜索** | 它找文献，不读数据文件。数据分析卡片**不接 minicod**（`AllowedMcpTools: []`，见 §4.1 裁决 6） | 用户问"这个方法同领域常用吗"→ 卡片建议转智能搜索，不自己检索。理由：C2 §Q1-14，`researchTurn.ts:78-88` 的 Router 以"本轮实际发给模型的工具名"判形态，`hasRetrieval` 需 `mcp__` 前缀工具；空白名单 ⇒ 恒判 `chat` ⇒ 证据预检索不触发，纯统计 feature 天然不被加一枪检索开销 |
| **Prism 智能写作** | 数据分析止于**稿件的一节**（表 + Methods 段 + Results 段），Prism 负责把它装进全文并管引用/编译 | A4/B1 双重红线："不做我帮你写完整篇论文"。P1 做流转：把 `out/` 里的 docx 表 + Results.md 一键送进 Prism 项目 |
| **科研绘图 sci_draw** | **数据分析出统计语义与带标注的统计图；sci_draw 出示意图/机制图/分子结构，以及对已有图的期刊配色重排** | 🔴 这条最容易漂。A5 说"数据分析只负责算出哪几组显著、字母怎么排，把结构化结果交给绘图能力渲染"，但**工程上没有跨 feature 调用通道**（C1 §1.4 每 feature 独立 13 条路由 + 独立 session）。裁决：**带显著性标注的图必须在数据分析卡片内由确定性 figures 模块产出**——因为星号/字母/CI 必须与 bundle 数字同源，跨进程传递等于给数字幻觉开一个新口子（A6 §八6 的"两份规范必然漂移"在这里反而支持不拆）。sci_draw 的边界收窄为"我要一张图"，数据分析是"我要一个结论（顺带一张图）" |
| **AI 审稿 peerreview** | 审稿卡片吃**稿件**；数据分析卡片吃**数据**。"这个结果能不能发"由审稿卡片以"审稿人会问什么"的形态回答 | A6 §八3 明确：数据分析卡片**不做**"能不能发/几区"的结论性判断（输出的是学术主张，错了责任在我们，且客观上无稳定判据——只有约 5% 的 WAME 期刊明文引用统计报告指南）。数据分析只出"六项最低必报项自检清单"（§3.3） |
| **智能助手 claw** | claw 是通用兜底。数据分析是**独立入口**，不是 claw 的一个 mode（裁决见 §4.3） | claw 里已有的 `methods-stats` / `data-figures` 两份 guide 保留，但降级为"claw 里顺手算一下"的轻路径；重活引导到数据分析卡片 |

## 二 · 交互形态设计

### 2.0 先说工程约束（决定了交互能长什么样）

前端可调旋钮的**完整清单**是 `frontend-user/src/features/claw/components/chat/ConversationWorkspace.tsx:41-66` 的 `WorkspaceConfig` 接口，共 14 个字段：

```
title / titleIcon / modelFeature / newConvModel / artifactBasePath
hero{title, subtitle, suggestions[]} / emptyArtifactsHint
figuresInline? / autoOpenLatestArtifact? / enableAttachments? / composerPlaceholder?
layoutKey / railSectionId / railLabel
```

🔴 **没有"自定义表单槽位"**。所以"目标体系选择器"这类结构化输入**只能落在会话内的 AskUserQuestion 卡片里**，不能做成第一屏的下拉框——除非另写前端定制组件（评估为不值得，理由见 §2.3）。

三个本次复核确认的事实：
- `figuresInline` 与 `autoOpenLatestArtifact` 是两个**独立的可选布尔**（`ConversationWorkspace.tsx:54-57`），语义不冲突：前者让图片类产物内联进对话流、不出文件卡；后者让新产出自动打开右侧预览面板。**两者可同时为 true** —— 正是本卡片想要的（图内联看，docx 自动开面板）。
- `modelFeature` 是联合类型 `'claw' | 'boltslides' | 'sci_draw'`（`ConversationWorkspace.tsx:46`），必须扩。
- `AskUserQuestion` 的硬约束（本次复核 `agent/src/tools/registry.ts:994-1009`）：**1–4 题**，每题 **2–4 个选项**，`header` ≤12 字。工具描述里还有两条对我们直接有效的规则（`registry.ts:990`）：「**有常规默认值的选择，直接选默认并在回复中说明，不要问**」「**不要用它来问『计划可以吗 / 要不要继续 / 这样对吗』这类确认**」。后一条直接否掉了"用 AskUserQuestion 做计划确认"的方案（见 §2.4）。

### 2.2 上传数据后的第一次响应：数据体检，不是提问

🔴 **裁决：第一次响应必须是一份"数据体检"，不能是问题，也不能直接开始分析。**

理由三条，各来自不同调研：
- B3 §八2："第一步必须是数据体检报告，而不是选择分析方法。这是所有竞品都跳过的一步（它们假设你的表已经干净），也是最容易在 30 秒内建立信任的一步——用户会立刻发现『它真的看了我的数据』。"
- B4 F11（看不见大猩猩）的防线是"**不依赖模型注意到，靠代码必然呈现**"：每列分布、缺失热力图、离群点计数、常数列、重复行、疑似 ID 列被当数值、日期解析失败、类别列基数爆炸。
- A7 §3.1 的硬数字：2014–2020 年 PubMed Central 上带 Excel 补充文件的基因组学论文里，**30.9%（3,436/11,117）含 Excel 自动改数据导致的基因名错误**，*Cell*/*Nature*/*PNAS*/*Cell Reports*/*Oncogene* 的错误率超 40%。这不是"用户不小心"，是软件默认行为造成的系统性污染——**替用户查一次是确定性的、不需要模型推理、且从来没人替他做过**。

四条设计约束：
- **不静默执行破坏性默认行为**（A5 红线，点名竞品 ChatSRS 的"完整案例删除"会让某时间点缺失的被试从全部时间点消失而用户毫不知情）。上面每一条"已自动处理"都必须**可点开看原始 vs 处理后**。
- **疑似缺失码只提示不擅自处理**（A7 §1.1：SPSS 用户常用 99/999 且在 SPSS 里登记为 user missing，导出 CSV 后这个机制丢失，999 变成真实数值进入均值计算——"灾难"）。
- **体检**不进模型上下文全文。全量逐列 profile 落 `profile.full.json` 只给引擎消费，模型侧只拿 ≤4KB 聚合摘要（旧方案 §2.3 的 DataProfile 分层设计仍成立，200+ 列的宽数据会撑爆上下文）。
- **必须走独立读取路径**。🔴 绝不复用 `ReadDocument` 的 xlsx 文本抽取通道 —— A7 §2.2 实测 `agent/src/tools/xlsx2text.py` 有三个会静默吞数据的降级：`read_only=True` 让合并单元格塌成 None（中文表格里"组别"合并三行极常见）、`data_only=True` 在从未被 Microsoft Excel 保存过的文件（WPS/Google Sheets/仪器导出）上让**所有公式格返回 None**、stdout 8MB 闸 + 60s 超时会**静默截断**大表。数据分析必须在沙箱内用 pandas/openpyxl 直读原文件。

### 2.3 问诊：最多两轮、总共 ≤6 题，能推断的绝不问

**为什么必须问**：这是全场唯一的空位。B1 §三的核心洞察——*Cureus* 2025-10 那项研究里六个模型在"选哪个统计检验"上 100% 正确，因为**场景是被人类完整规范地描述好了才喂进去的**；而 JCO CCI 用真实病人级原始数据让 AI 自主复现结论时，ChatGPT-4o 的**统计方法选错率是 38.4%**。差的就是"把研究设计问出来"这一步，**现在没有任何一个产品在做**。

**为什么不能多问**：A1 明确"目标用户的时间窗是晚上 10 点后的两小时；一次上传 → 一次问清关键设定 → 一次出全套。**超过 3 轮往返用户就回去找淘宝 ¥100 的代做了**"。

**机械化的"问什么"规则**（不是靠 prompt 叮嘱模型自觉）：

B4 F10 的实证是 **Ambig-DS 证明模型无法可靠判断何时该问**（要么在清晰任务上过度提问，要么在歧义任务上静默默认）。所以：**别让模型决定要不要问，用确定性触发器**。

| 轮次 | 题目 | 触发条件 | 选项形态 |
|---|---|---|---|
| **第 1 轮（必问，恒 3–4 题）** | | | |
| Q1 | **这一行代表什么？哪一列标识独立的实验/观测单元？** | 恒问，**不可跳过** | 「一个病人/被试」「同一对象的一次测量（有重复）」「一个技术重复（同一样本测多次）」「说不准，帮我看」 |
| Q2 | **你想比较/分析的是哪个结局？按什么分组？** | 恒问 | 从 profile 的 `grouping_candidates` 里挑 2–4 个具体列名当选项 |
| Q3 | **目标期刊体系** | 恒问 | 「中文核心/学位论文」「医学英文刊（AMA/NEJM）」「心理教育（APA 7）」「经济管理」 |
| Q4 | **配对还是独立** | 仅当 Q1 答"有重复"或检出疑似配对结构时 | 「同一批人前后测」「两组不同的人」「不确定」 |
| **第 2 轮（仅触发时问，≤2 题）** | | | |
| T1 | 分组 >2 水平 → 事后两两比较的口径 | 分类列水平数 >2 | 学科默认值预填（见下） |
| T2 | 存在时间列 + 事件列 → 是否做生存分析 | 检出 time+event 形态 | — |
| T3 | 检出缺失 >5% → 缺失如何处理 | 缺失率阈值 | 「完整案例（并告诉我删了几个）」「按变量成对删除」「先看看缺失模式」 |
| T4 | n<30 或分组后单元格频数 <5 | 恒硬闸 | 见 §2.6 小样本闸 |

**避免问烦的四个机械手段**：
1. **能从 profile 推断的绝不问**——这是 `AskUserQuestion` 工具描述自己的第①条规则（`registry.ts:990`："有常规默认值的选择，直接选默认并在回复中说明，不要问"）。列类型、分组水平数、样本量、缺失率全部由体检推断，不问。
2. **一次问全**（工具描述第②条："不要挤牙膏式连问"）。第 1 轮把 3–4 题一次性发出。
3. **学科默认值预填**：Q3 一旦选定体系，后续所有格式问题都不再问（p 值写法、小数位、括号放 SD 还是 SE、星号阈值全部由体系决定，A6 §3）。事后检验的默认值按学科走——🔴 **农学/食品默认 Duncan 不默认 Tukey**（A3 明确："统计上 Tukey 更对，但农学审稿人的默认是 Duncan；可以提示更严格，默认必须跟随学科惯例，否则用户投稿被导师打回就再也不用了"）。
4. **答案落库，重开会话不重问**。旧方案 §5 的 `consult --answers` verb 设计成立且必须保留：模型把答案整理成 JSON 交给引擎写 `project.json`，LLM 自始至终不直接写状态真源。

### 2.4 计划确认：不用 AskUserQuestion，用一张"分析计划卡" + 一句话

🔴 **裁决：计划确认走产物面板里的 `plan.md` + 对话里一句"确认就说『开始』，要改直接说改哪"。**

**被否决的方案**：用 `AskUserQuestion` 弹一张"计划可以吗？[可以 / 要改]"。
**否决理由**：`registry.ts:990` 的工具描述第④条逐字写着「**不要用它来问『计划可以吗 / 要不要继续 / 这样对吗』这类确认**」，且 `turnLoop` 在 AskUserQuestion 被调用后会强制收尾（askFired wind-down，`registry.ts:983`）——用它做确认等于每次都白烧一整轮。

**计划卡长什么样**（内联 + 落 `plan.md`）：

```
📐 分析计划 · 待你确认

  研究设计   两组独立样本（对照组 n=428 / A方案 n=431），结局=术后住院天数
  目标体系   中文核心期刊（三线表 / x̄±s / P 值报精确值 / 星号 * ** ***）

  1️⃣ 基线表（Table 1）
     47 列里选 18 列进表 · 连续变量先测正态性再决定 x̄±s 还是 M(P25,P75)
     组间检验按类型自动分流 · 报缺失例数
     └ 我选了哪 18 列 · 为什么排除另外 29 列          [展开]

  2️⃣ 主结局：术后住院天数 ~ 组别
     ① 先测：Shapiro-Wilk（正态性）+ Levene（方差齐性）
     ② 按结果自动分流 —— 满足→独立样本 t；方差不齐→Welch；非正态→Mann-Whitney
     ③ 无论走哪支，都报效应量（Cohen's d 或 r）+ 95% CI
     ⚠️ 分流依据会一起写进 Methods，不只给你结论

  3️⃣ 交付
     Table1.docx（可编辑三线表）· 主结果表.docx · Methods统计段.md
     · Results段_中英.md · analysis.py（含随机种子与版本清单）· 自检清单

  ❌ 这次不做：多因素回归（你的数据里没有明确的混杂变量清单，
     要做的话告诉我控制哪些变量）

  确认就说「开始」；要改直接说改哪一条（比如"基线表里加上 BMI"）。
```

四条设计要点：
- **分流依据先声明**（"按结果自动分流"而不是"我帮你选了 Welch"）。A5 需求 TOP3 逐字："审稿人问的是依据不是结论"。
- **显式写"这次不做什么"**。这是把"贫瘠的分析"（B4 §1.3 BLADE：模型的分析决策会塌缩到最平庸的一小撮）变成可见的、用户能补的东西。
- **计划是可编辑的自然语言**，不是表单。这是与 SPSSAU/SPSSPRO 的形态分界线（B3 §七2："不做零代码点选式统计向导——那是 L1 主场，做成表单我们就变成了一个 UI 更差的 SPSSPRO"）。
- 用户说"开始"后**不再中途询问**，一路跑到交付（除非撞硬闸）。

### 2.6 三类硬闸（确定性，不问模型）

| 闸 | 触发 | 行为 | 依据 |
|---|---|---|---|
| **小样本闸** | n<30，或分组后任一单元格期望频数 <5 | 不放行参数检验。给三条路：精确检验（Fisher）/ 非参 / 明说"样本量不足以支持推断"并给功效计算 | B1 §七9。竞品在这里编数据（30–50 行阈值——⚠️ 但该阈值唯一来源是 Julius 的直接竞品营销页，B1 更正 #7 已降级为"竞品主张，置信度 low"；真正硬的是同行评议的 38.4% 方法选错率） |
| **多重比较闸** | 会话内累计假设检验数 >1，且用户引用了 >1 个 p 值 | 自动附 BH/Bonferroni 校正后的 q 值。**纯记账，代码数，不问模型**（B4 §九10） | A1 逐字给了最好的功能说明："那 28 项研究校正后只剩 13 项显著" |
| **伪重复闸** | Q1 未答 / 答"说不准" | **不可跳过**。必须确认独立单元后才放行 | A5 最锋利的一条：伪重复"在任何输出上都不可见"——同一份 30 行数据按独立样本还是按 3 重复×10 复孔解读，SD 差一个量级、p 差一个数量级，**而两种情况程序都跑得通、图都正常、零警告**。体育科学实测 46% 的研究栽在这里 |

### 2.7 用户说「我要 p 值显著」怎么办

采纳 A7 §6.2 的**三层模型**（这是本次调研最重要的设计洞察之一：大部分这类请求用户自己并不认为是造假，因为方法学文献里确实写着这些做法）：

| 层 | 判据 | 我们的动作 |
|---|---|---|
| **L1 合法方法学调整** | 有预设依据、会被报告 | 正常做，自动记进分析日志 |
| **L2 灰区（QRP）** | 做法本身合法，但**依据是"结果好不好看"**、且不打算报告 | **做，但强制留痕 + 主动提示** |
| **L3 明确造假** | 改数值、编造观测、直接改 p、反向搜索式剔除 | **硬拒，无例外** |

**L3 拒绝话术模板**（原则：不说教，直接给替代路径——空的拒绝会把用户推去淘宝，那里 ¥300 就能买到）：

```
改数值这一步我不做 —— 这会让整篇文章在任何一次原始数据核查里崩掉，
代价不是退稿是撤稿。但你现在这个情况我能帮上：

① p=.062 且方向一致 → 报**效应量 + 95% CI** 比报 p 更有说服力，
   Nature Reporting Summary 第 7、10 条本来就要求必报效应量与 CI；
② 我可以算当前样本量下的实际功效。如果是 power 不足，这是可以
   写进 Limitations 的**正当理由**，不是遮掩；
③ 你这份数据是三个时间点的重复测量，现在按独立样本在算 ——
   换成混合效应模型本身就可能改变结论。这是方法学修正，不是调数。

要走哪条？
```

**L2 的处理**（照做 + 留痕 + 说出来）：

```
已按你的要求剔除 2 个观测（ID 17、43）。

  剔除前  t(58)=1.87, p=.067, d=0.49
  剔除后  t(56)=2.34, p=.023, d=0.62

提醒：如果剔除依据是"看了结果之后"而不是预设的离群值规则，
投稿时需要在 Methods 里说明剔除标准与剔除数量 —— STROBE/CONSORT
都要求这个。我把两版结果都留在了「分析尝试记录表」里，
你决定报哪一版，或者两版都报（当敏感性分析）。
```

🔴 这一手把 QRP 变成了**可报告的敏感性分析**——这正是方法学家希望发生的事，也是**人类统计师做不到而我们能做到**的一件事：完整、自动、不可篡改的分析尝试日志。

**三条防谄媚的机械动作**（B4 F9：谄媚基本没有确定性防线，可做的只有这些）：
1. 系统提示词固化"先看数据再看用户的假设"的顺序；
2. 用户输入含明确方向性假设时（正则粗筛"我觉得 A 会提高 B"），**强制先跑一次无假设的描述性 EDA 并展示**，再进检验；
3. 结论页固定一栏「**与你的预期相反的发现**」，即使为空也显式写"无"。

**不要过度拒绝**（A7 §6.3 边界的边界）：生成模拟数据做功效分析/教学、"结果不显著怎么写讨论"、"多重比较校正后全没了怎么办"、"把图做好看点"——**全部合法必须做**。判据只有一条：**是否改变了对真实观测的忠实呈现**。

### 场景 B · 农学/食品（多组 + 事后 + **a/b/c 字母标记**，英文期刊）

> 用户画像：农业院校硕士三年级，一份 xlsx 里 6 个 sheet（SOD、POD、CAT、MDA、可溶性蛋白、脯氨酸），每个 sheet 都是 5 个处理 × 3 次重复，要出一张能投稿的图。

**屏 1** —— 拖入 `盐胁迫生理指标.xlsx`。

**屏 2** —— 体检卡额外识别出本集群独有的形态：
```
  📋 检出 6 个 sheet，结构一致（5 处理 × 3 重复）
     SOD · POD · CAT · MDA · 可溶性蛋白 · 脯氨酸

  ⚠️ n=3 —— 每个处理只有 3 个观测。这个样本量下：
     · 正态性检验几乎没有检出力（Shapiro-Wilk 在 n=3 时形同虚设）
     · 我会直接报效应量与均值±SD，并在 Methods 里如实写明 n=3
     · 这在你这个领域是常规做法，不是问题，但要写清楚

  ❓ 关键问题：这 3 个重复是 3 株不同的植株，还是同一株测了 3 次？
     —— 这两种情况的 SD 会差一个量级，而程序都跑得通、图都正常。
```
🔴 这条追问是**不可跳过的硬闸**（§2.6 伪重复闸），A5 逐字给的理由。

**屏 3** —— 问题卡（3 题）：
```
①【重复的性质】3 个重复是？
   ○ 3 株不同的植株（生物学重复，推荐）
   ○ 同一株测 3 次（技术重复 —— 我会先取平均再比较）

②【批量还是逐个】6 个指标怎么处理？
   ○ 6 个指标跑同一套分析，合并成一张大表（推荐）
   ○ 一个一个来

③【显著性标记法】
   ○ 小写 a/b/c（P<0.05）+ 大写 A/B/C（P<0.01）双水平（推荐 —— 农学惯例）
   ○ 只要星号 * ** ***
   ○ 两种都出
```
「一个 xlsx 内多 sheet / 多指标批量跑同一套分析并合并成一张大表」是 **A3 明确标注为"本集群独有且现有工具全不支持"** 的能力。

**屏 4** —— 计划卡里的一条关键分流声明：
```
  2️⃣ 每个指标：单因素 ANOVA → 事后多重比较
     · 事后方法默认 **Duncan**（跟随农学/食品期刊惯例）
       ⓘ 统计上 Tukey 更严格，要换告诉我；但 Duncan 是你这个领域
```

### 场景 C · 「不传原始数据」入口（SPSS 输出翻译 → Results 段）

> 用户画像：教育学在职硕士，SPSS 已经跑完了，卡在"这堆表该往论文里写哪几个数"。数据涉及未成年学生，她不敢往任何在线平台传原始表。

**屏 1** —— hero 页的第三条 suggestion：`我有 SPSS 跑好的结果，帮我翻成 Results 段`。点击 → composer 预填一句话 + 引导：
```
  把 SPSS 输出**截图**（或导出的 Word / PDF）传上来就行 ——
  不需要你的原始数据。我只读表里的数字。
```

**屏 2** —— 用户传 3 张截图（png，走 vision 白名单，`upload.go` 的 jpeg/png/gif/webp）。

**屏 3** —— 结构化回读（**不是解读，是先把读到的东西摆出来让她核对**）：
```
  📖 我从 3 张图里读到这些（请核对，读错了直接说）

  ① 独立样本 t 检验 · 后测成绩
     实验组 n=30, M=85.6, SD=4.2
     对照组 n=30, M=78.3, SD=5.1
     Levene F=0.83, p=.366        → 方差齐
     t=6.05, df=58, Sig.(双尾)=.000

  ② 单因素 ANOVA · 学习动机
     F(2,87)=5.42, Sig.=.006
     LSD 事后：A-B p=.003, A-C p=.041, B-C p=.612

  ③ 相关分析（Pearson）
     动机 × 成绩 r=.412, Sig.=.000, N=90

  ⚠️ 三处需要处理的问题：
   · ①③ 的 Sig. 显示 .000 —— 这是 SPSS 只显示三位小数的假象，
     **论文里绝不能写 p=.000**，要写 p<.001
   · ① 你没有报效应量。APA 7 要求必报，我可以从 M/SD/n 反算 Cohen's d
   · ② 用的是 LSD 事后 —— 它不做多重比较校正，审稿人常在这里挑刺。
     要不要我同时给一版 Bonferroni 校正后的结果？（数据在你手上，
     我只能用你截图里的数反算，会告诉你哪些是反算的）
```

**屏 4** —— 产出（APA 7 体系）：
```
  📁 out/
   ├ Results_APA7.md    ← 模板填空生成的成句文字
   ├ 结果表_APA7.docx   ← 只有横线无竖线的 APA 表
   └ 审稿人可能会问.md
```
`Results_APA7.md` 的内容形态（**模板插值，不是模型自由生成**）：
```
  独立样本 t 检验结果显示，实验组后测成绩（M = 85.60, SD = 4.20）
  显著高于对照组（M = 78.30, SD = 5.10），t(58) = 6.05, p < .001,
  Cohen's d = 1.56, 95% CI [0.97, 2.14]。

  ⓘ Cohen's d 与其 CI 由你提供的 M/SD/n 反算得出，非 SPSS 原始输出。
```

#### 🔴 场景 C 的硬约束：这条入口**破掉了 §4.1 表②的架构第一约束**，必须单独设闸

§4.1 把"报告里的数字来源"列为**架构约束**（模型只写骨架，数字由渲染层从 bundle 取值），§7.1 拿它当差异化第 3 条。但场景 C 的链路是 **用户传截图 → 模型 OCR 读数 → 反算 Cohen's d → 填进 Results 模板**，**每一个数字都来自模型的视觉识别**。原稿只在文案里加了一个 ⓘ 免责括号，而 V1–V5 五条上线闸**没有任何一条测这条路径的读数准确率**——也就是说，P0 的零门槛旗舰入口是全案唯一一处"数字确实经模型手"的地方，且零验收。

**三条必须做成机制而不是措辞的约束**：

1. **结构化回读表必须逐项确认后才写进 bundle。** 屏 3 那张"我从 3 张图里读到这些"不是展示，是**表单**：每个字段旁有 `✓/✗`，用户逐项确认（或一键"全部正确"）；**未确认字段不得进 bundle，`report` verb 遇到 `confirmed:false` 的字段直接拒绝渲染**（退出码 2）。工程上就是给 bundle 的每个数值字段加一个 `provenance` 三态：
   - `computed` —— 引擎从原始数据算出（场景 A/B 的默认，可直接渲染）
   - `read_confirmed` —— 模型读出、**用户已确认**（场景 C 唯一可渲染的态）
   - `read_unconfirmed` —— 模型读出、未确认（**硬拦**）
2. **反算量必须带来源标记，且标记由渲染层加、不由模型写。** 现在文案里的 ⓘ 是模型写的一句话，模型可以忘。改成：`provenance != "computed"` 的任何数值，`report` verb **自动**在脚注追加"该值由 <来源> 反算/读取"。这是把措辞变成机制。
3. **不做多层反算。** 从 M/SD/n 反算 d 可以；从"已反算的 d"再反算别的量（如从 d 反推 CI 再反推 p）**禁止**——误差会被逐层放大且不可见。`emit` 校验：`provenance=read_*` 的字段最多参与一层派生。

**新增上线闸 V6（补进 §6.2）**：

| # | 验收项 | 判定方式 | 阈值 |
|---|---|---|---|
| **V6** | **SPSS 输出读数准确率**（场景 C 专项） | **20 份真实 SPSS 输出**，构成必须覆盖：WPS 截图、手机拍屏/低分辨率、**中文表头与中文变量标签**、SPSS v25–29 跨版本、深色主题截图、含被裁切的表。逐字段比对（n / M / SD / F / t / df / Sig. / 事后 p 矩阵） | **字段级准确率 ≥ 98%，且"读错且用户未察觉"的漏网率 = 0**（后者靠约束 1 的逐项确认机制保证，不靠模型）。任一字段读不出 → 必须显式空缺并追问，**不得猜** |

⚠️ **这 20 份样本与 §十-2 的"30 份真实脏数据"是两批不同的东西**（那批是原始数据，这批是输出截图），征集时要分开说明，否则会只拿到一种。

**这条入口的三重价值**（A7 §0-3）：零隐私顾虑（`.spv`/截图里没有个案数据）、零学习成本、以及**它天然绕开了人遗条例与 PIPL 的全部锋利边界**。同时它正是 IBM AI Output Assistant / Minitab AI / JMP Assistant 三家大厂 AI 化押的同一件事（B2 §〇），而它们**全部锁在付费软件 + 海外账号内，中国用户三条全废**（B2 §1.4：要用得买 SPSS 31.0.1+、另注册 watsonx、网络可达 IBM 云；且 IBM 社区专帖显示 credential 故障到 2026-03 仍未解决）。

## 四 · 关键架构裁决

### 4.1 裁决 1：确定性引擎 vs 让模型自由写 Python —— 边界划在哪

**裁决：三夺权、三放手、一硬拦。P0 的引擎是一个 ~2400 行的 pip 包，不是旧方案的 7000–9000 行 StatEngine。**（逐块行数见 §6.3-T2；~1500 是本次修订前的估算，漏算了 §4.1.1–4.1.3 三块）

| 环节 | 归属 | 依据 |
|---|---|---|
| **① 前提检验（正态性/方差齐性/球形度/期望频数/VIF）** | 🔒 **确定性夺权** | StatQA：LLM 的**首要**错误类型是 applicability error（"知道该做 t 检验，但没意识到这份数据不满足前提"），且这一类**100% 可机械判定**。ROI 最高的一条 |
| **② 报告里的数字来源** | 🔒 **确定性夺权** | B4 F7 逐字："模型只写文字骨架和占位符，数字由渲染层从结构化 JSON 取值填入"。这**不是"加个校验"，是架构约束** |
| **③ 数据体检 + p 值格式化 + 三线表排版 + 多重比较记账** | 🔒 **确定性夺权** | B4 F11/F12；A6 §八7："p=.000 / p<.05 / NS 三种写法都是模型极容易生成、且在目标体系下明确错误的输出"，必须是吃「目标体系 + 原始 p」的确定性函数 |
| **④ 方法选择（在候选白名单内挑）** | 🤖 **放手给模型** | StatQA：GPT-4o 64.83% > 有统计背景者开卷 53.45%。规则引擎会**拉低水位**。⚠️ 但该人类基线 **n=6**（B4 更正 #48），只能算弱证据——所以放手的同时保留⑦的硬拦 |
| **⑤ 数据清洗 / 宽转长 / 多表合并** | 🤖 **放手给模型** | B4 §四5：LasRepair++ 在数据修复上比最强 baseline F1 +18.1%；且清洗错了容易被后续断言层抓到 |
| **⑥ 结果解读的定性文字、编排、与用户对话** | 🤖 **放手给模型** | B4 §四4："解释统计输出给非统计背景的人听是 LLM 的原生强项，别加防线，加体验" |
| **⑦ 事后一致性硬拦** | 🔒 **轻确定性** | 名义因变量 + 选了线性回归 → 硬拦；文字里写 "p<0.05 说明有显著差异" 而 bundle 里 p=.062 → 硬拦重写；观察性数据 + 因果措辞（"证明了/导致"）→ 硬拦 |

**被否决的方案 A：旧方案的完整 StatEngine（35 模块 / 7000–9000 行 / 车道 A 声明式执行）。**
否决理由：① C2 §2.2 实测 P0 现实工期 15–20 天而非 8 天，主要低估在 golden 参考值链路与 tests.yaml 的外部评审依赖；② B4 的证据不支持"计算本身是主要错源"——StatABench 的失败归因是工具选择 50% / 合规执行 26% / 结果解读 24%（⚠️ 且该分布来自 **n=38 的 DeepSeek 专项子集**，非通用分布，B4 更正 #43），纯计算不是瓶颈；③ scipy/statsmodels 的 API 模型本来就写得对。

**被否决的方案 B：完全不做引擎，纯 skill + prompt 约束。**
否决理由：`agent/Dockerfile:49-54` 记了完整事故链——SKILL.md 声明 statsmodels 可用而镜像没装，模型只剩"撞 ImportError"或"把数字编出来"两条路，后者正是审计里效应量凭空出现的机械成因。**prompt 叮嘱不是防线**。

**采纳方案：窄版引擎 `statkit`，六个 verb。**

```
statkit profile <file>          # 数据体检（分层输出：≤4KB 摘要给模型，全量落 profile.full.json）
statkit consult --answers <json>  # 把问诊答案 + 目标体系写进 project.json（唯一的状态写入口）
statkit assume --spec <json>    # 前提实测 + 决策表分流（返回 allowed[] / chosen / reasons[]）
statkit emit --result <json>    # 模型算完后把结果落 results/<hash>.bundle.json（引擎校验字段完整性）
                                #   --batch-key <col|sheet> 时按键分组批量落多份 bundle（见 §6.1 族 2）
statkit report --system <cn-core|apa> --bundle <...> --narration <md>
                                # 三线表 docx + p 值格式化 + 模板插值 + 六项自检
                                #   --merge <bundle...> 合并多指标为一张大表（场景 B）
statkit numcheck --observe      # 数字来源扫描（P0 只记录不拦，见下）
```

🔴 **`consult` 必须进 P0，原稿把它漏了。** §2.3-4 写着「旧方案 §5 的 `consult --answers` verb 设计成立且**必须保留**：LLM 自始至终不直接写状态真源」，但原稿采纳的五个 verb 里没有它，`project.json` 全文只出现两次、无 schema、也不在 §5.1 的产物清单里——**等于"返修二次进入"这条商业模型的核心资产在 P0 里没有任何落地物**（§7.1 拿它当竞品对比的一格）。

**`project.json` 字段表**（落会话 workDir 根，`consult` 是唯一写入者，`assume`/`emit`/`report` 只读）：

| 字段 | 类型 | 由谁产生 | 用途 |
|---|---|---|---|
| `schema` | `"statkit/project@1"` | consult | 版本化 |
| `created_at` / `updated_at` | ISO8601 | consult | 与 workDir GC 的 30 天窗口对账（见 §8.1-T11） |
| `source_files[]` | `{name, sha256, rows, cols, sheet?}` | profile → consult | **二次进入时判定"还是同一份数据吗"的唯一依据**——EBOSS 那条"若數據更改則另外收費"的技术对应物 |
| `answers` | `{unit_of_observation, dv, iv, pairing, subject_field, ...}` | consult（问诊 Q1–Q4 + T1–T4） | 重开会话不重问（§2.3-4） |
| `system` | `"cn-core" \| "apa"` | consult | report 的格式化分支 |
| `spec_history[]` | `{spec_hash, verb, at, bundle_ref}` | assume/emit 追加 | 幂等锚 + §8.2-M8 要求的"所有跑过的模型规格账本" |
| `deliverables[]` | `{path, kind, from_spec_hash}` | report 追加 | 产物 ↔ bundle ↔ spec 的三层可下钻（B2 §八c） |
| `revision_round` | int | consult（每次带审稿意见重入 +1） | **返修计费的计量单位**（见 §7.3-4 的成本拆分） |

成本：`consult` 是纯 JSON 读写 + 字段校验，**~80 行**，已计入 §4.5 重估后的 T2。

**关键的形态简化**（相对旧方案）：引擎**打成 pip 包装进 `dist-packages`，不放 `/opt/statengine`**。
- 依据：C2 §Q1-3。pip 装的包落在 `/usr/local/lib/python3*/dist-packages`，已被 `agent/src/sandbox/bwrap.ts:93` 的 `--ro-bind /usr /usr` 覆盖（**lifelines 0.30.3 就是活证据**，`agent/Dockerfile:73-74`）。
- 收益：`bwrap.ts` **零改动**、`registry.ts` 的 `bashEnv()` **零改动**（旧方案 §2.1 要改的两行 PYTHONPATH 不需要了），连带旧方案为"跨 feature 暴露面"写的那整段裁决理由也不需要了。

**numcheck 分两步发布**（照 `citation_audit` 的纪律，C2 §4.3）：
- **P0 只做结构保证**：report verb 从 bundle 取值填模板，文字里的数字物理上不经模型手；
- **numcheck 扫描先跑 observe 模式**（只记录假阳性率，不拦截），两周后再决定开硬拦。理由：numguard 的容差匹配/中文数词归一/白名单是**启发式**，是全方案误拦风险最高的一块，且**没有任何现成代码可抄**（C2 §4.2-2：证据账本这边的对等物 `citation_audit` 同样从未实现，grep 零命中）。

**不做的三件**（相对旧方案的删减）：
- ❌ 图片旁路堵截（`figures_manifest.json` + verify 扫 out/）—— P1。P0 靠"统计图只许 report verb 出"的 skill 红线 + 抽样审计。
- ❌ PCS 扰动稳定性独立 verb —— P1。P0 只做"非参对照复核"这一条最便宜的（跑一次 Mann-Whitney 对照 Welch t，结论不一致就如实说）。
- ❌ 声明式 AnalysisSpec 的完整 JSON Schema 车道 A —— P0 的 spec 收窄到 8 个字段（design/dv/iv/pairing/direction/alpha/family/system）。

#### 4.1.1 bundle JSON 字段表（**决定 T2 的第一样东西，原稿缺失**）

`results/<hash>.bundle.json` 是全案的数字真源：`report` verb 只从这里取值填模板，**文字里的数字物理上不经模型手**（§4.1 表②的架构约束）。`emit` verb 的职责就是校验下表的必填字段齐全，缺一项即拒收（退出码 2）——**这是"数字锁"唯一真正的执行点**，写不出这张表 = 那条架构约束只是一句话。

**公共必填（每个 bundle 恒有）**：
```jsonc
{
  "schema": "statkit/bundle@1",           // 版本化，改字段必升版
  "spec_hash": "sha256:...",              // = 8 字段 spec 的内容 hash，verb 幂等的锚
```

### 4.4 裁决 4：`.sav` / `.dta` 直读 与「SPSS 输出翻译」入口

#### (a) `.sav`（SPSS 原生数据）—— **P1，不进 P0**

**能力上完全可行且价值极高**：pyreadstat（**Apache 2.0**，底层 ReadStat MIT，A7 §1.1 判定为"所有候选方案里许可证最干净的一条路"）能读出变量标签、值标签、用户缺失值区间、measure、display width。

🔴 **元数据才是资产，不是数据**（A7 §1.1 的决定性观察）：中国用户的 `.sav` 里变量名是 `a1 a2 q12_1`（SPSS 不支持中文变量名，经管之家老帖的通行做法是"变量名用英文，中文写在变量标签里"），**「您的最高学历」「术后30天再入院」这些中文全部只存在于 variable label 里**。任何用 `pandas.read_spss()` 只拿 DataFrame、丢掉 metadata 的实现，等于把用户的数据变成一堆无名列——**AI 会立刻开始瞎猜列的含义，这是幻觉的机械成因，不是模型不聪明**。

**为什么推 P1**：需要四层齐改（C1 §8.3 / C2 §Q1-6）——
1. `agent/Dockerfile` 加一层装 pyreadstat（pip，有 C 扩展）；
2. `agent/src/tools/statsEngines.ts:31-40` 的 `DECLARED_ENGINES` 同步（C1:318 定的纪律："改 SKILL.md 必须同步改它"）；
3. `backend/internal/agentattach/upload.go:322-347` 白名单——⚠️ 注意 `.sav` 是**二进制**，不能塞进 `isPlainText` 的 switch（`:330-335`），要加一个 `isDataFile` 分支；
4. `frontend-user/src/shared/hooks/useComposerAttachments.ts:28` 的 `DOC_EXTS`——`:23-25` 头注释明写"镜像 upload.go 的分类谓词，**两侧同步改**"。

而 **A7 §2.1 的铁律是「收 = 能读」**：`upload.go` 文件头注释逐字写着"凡容器内没有解析路径的格式一律在入口拒收，**绝不让『传上去了 AI 却打不开』的断层发生**"。所以扩白名单与装解析器必须同一次上线——P0 已经很满，这四层一起塞进去会挤掉更重要的东西。

#### (b) `.dta`（Stata）—— **P1，与 .sav 同批**

pandas 自带 `read_stata`（纯 Python，无需 pyreadstat），**容器侧零改动**，只需白名单两侧各加一行（C1:546）。⚠️ 但 C1 §十 标注"`pandas.read_stata` 在本容器实测未跑，结论是推断"——**上线前必须在真 jail 内实测**。
另有一个必须处理的坑（A7 §1.4）：**DTA 118（Stata 14+）之前的版本不声明文本编码**，中国经管用户手上大量 Stata 12/13 时代的 `.dta`，中文标签是 GBK 裸字节，ReadStat 遇到无效字节会直接抛 `ReadstatError`。**必须做"先试 UTF-8 → 退 GB18030 → 退 latin1 并告知用户"的三级探测**，不能让异常裸奔。

#### (c) 「SPSS 输出翻译」—— **P0 做，但入口不是 `.spv`**

🔴 **这是本文对旧方案与 A7 的一处重要修正。**

A7 §0-3 判定 `.spv` 是"被严重低估的切入点"（PSPP 的 `pspp-output convert` 能转 csv/html/txt，格式规格由 PSPP 开发者基于约 8000 个真实文件逆向）。**方向对，但载体选错了。**

**裁决：P0 的低门槛入口是「上传 SPSS 输出的截图 / 导出的 Word / PDF」，而不是解析 `.spv`。**

四条理由：
1. **零新依赖**。容器已有 `ReadDocument` 支持 pdf/docx（`agent/src/tools/registry.ts:544`，C1:370），上传白名单已含 `.pdf`/`.docx`（`upload.go:343-347`）与 vision 白名单图片。**今天就能做，一行工程改动都不要。**
2. **专做这行的团队选了同样的路**。Uedufy 的 Chapter 4 Interpreter 吃的是 **SPSS 导出的 PDF**（v25–29）而不是 `.spv`（B2 §Q3）——"一个专门做这行的团队选了更笨的路线，大概率有原因"。
3. **`.spv` 的两个未解风险**：A7 §八1 自陈"`pspp-output` 对中文 `.spv` 的保真度未实测"，是它自己那条结论**唯一的风险点**；且 PSPP 是 **GPLv3**，打进 Docker 镜像分发需要合规确认（子进程调用不传染，但要走一次法务判断）。
4. **SPSS 版本碎片化**（B2 §七2）：中国用户手里多是破解版，版本比 Uedufy 声明的 v25–29 更乱。

`.spv` 原生解析降到 **P2，且立项前必须先拿真实中文 `.spv` 实测一次**。

🔒 **一条必须在设计上锁死的不对称**（A7 §七8）：**读 `.spv`（翻译成论文段落）价值极高；写 `.spv`（生成一个假的 SPSS 输出文件）只有造假一个用途。** 永远不做写回。

**据此，V1 的 golden 参考包必须扩容**（§6.2）：原定 `car / emmeans / survival` 覆盖不了 Duncan 与 CLD——
- **`agricolae`**（R，`duncan.test()` / `LSD.test()` / `SNK.test()`，且其 `groups` 输出**就是字母标记**）——Duncan 与字母排布的参考真源；
- **`multcompView`**（R，`multcompLetters()`）——CLD 的独立第二参考，用来交叉验证 `compact_letter_display()` 的 insert-absorb 结果；
- `car`（Levene）/ `emmeans`（Games-Howell、事后对比）/ `survival`（P1 生存）保留。
> 字母标记不是"算个数"，是一个**图着色式的归并算法**（把两两显著矩阵压成最少的字母集，同字母 = 不显著）。同一份 p 值矩阵，不同实现给出的字母**可以都正确但不相同**（字母顺序、是否按均值降序重排）。所以 V1 对 CLD 的断言不能用字符串相等，**必须断言"同字母组的集合划分等价"**，并单独规定"字母按均值降序从 a 开始"这一条排版约定。

⚠️ **不能引 pingouin**：GPL-3（C2 §Q1-2 明确"排除理由是 license 不是安装通道，pip 通道开了也不能引"）。`factor_analyzer`（GPL-2）同理。B2 §四4 建议的"pingouin 是最优先依赖"这条**必须拒绝**——但要说清楚拒绝的代价：pingouin 里我们真正会用到的是 `welch_anova` / `pairwise_gameshowell` / `compute_effsize` + `compute_esci`，其中前两项由 MIT 的 scikit-posthocs 覆盖，只剩效应量与其 CI 那 ~130 行要自己写。**原稿写的"自己写 ~200 行即可覆盖"方向对，但那 200 行原本被算在了"P0 不缺任何东西"的前提下，等于没进任何一处工期表。**

**但 R 有一个不可替代的用途**：**golden 回归的参考值**。

### 5.4 六项最低必报项自检清单（硬闸，不是装饰）

A6 §4.6 把 Nature Reporting Summary、SAMPL、ARRIVE、PRISMA、ICMJE 求交集得到的**任何学科都不会错的六项**：

1. **精确样本量 n**（每组、每分析；含分母）
2. **效应量**（并说明怎么算的）
3. **95% 置信区间**（不是 SE）
4. **精确 p 值**（不写 NS、不写 p<0.05、不写 p=.000）
5. **检验前提是否满足 + 多重比较是否校正**
6. **缺失数据如何处理 + 统计软件与版本**

**P0.5（P0 末尾，各 0.5 天）**：
- **Cronbach α + 相关矩阵** —— C2 §Q5 的修正是对的：α 用 numpy 十行，**覆盖整个问卷人群**（SPSSAU 覆盖 95% 高校、问卷星免费版 1000 份卡脖子的那批人）。推到 P1 等于 MVP 不覆盖研究生这个最大人群。
- **浏览器端上传前标识列体检** —— A7 §5.6-4。前端已有 SheetJS（`frontend-user/package.json:88` 的 `xlsx@0.20.3`），读表头正则匹配「姓名/身份证/手机/住院号/门诊号/病案号/联系方式/地址」并提供一键删除。成本极低，**比任何隐私声明都有说服力**。

**明确不进 P0**：回归族（线性/logistic）、生存分析（KM/Cox）、ROC/列线图、EFA/CFA、PROCESS 中介调节、重复测量 ANOVA、面板固定效应/DID、样本量与功效、Meta 分析。

理由不是"不重要"，而是 **P0 的目的是把"体检 → 问诊 → 守门 → 合规交付"这条闭环做到无可挑剔**。B2 §七1 逐字："SPSSAU 有 500 类方法、SPSSPRO 有 360+ 算法，拼数量我们进去就垫底且永远打不完。"A1 说得更狠："覆盖 90% 医学论文实际用到的约 15 个方法但每个都出到可投稿成品，胜过堆 200+ 方法。"

**P1 的排序**（按需求侧证据强度，非教科书顺序）：生存分析（lifelines 已在镜像，成本降到"接一个 verb"，C2 §Q5-3）→ 单因素→多因素 logistic 二连表（A1 需求 TOP3）→ 回归族 → EFA/CFA → 重复测量 + 球形度校正（A5 体育第一卡点）→ `.sav`/`.dta` 四层齐改 → `.do` 预览一行 → Prism 流转。

- **被打掉的**：不能再说"把结果变成能粘进 Word 的表"整体是空位——**APA 那一格已有免费玩家**，而且它同时解决了 `.sav` 直读（我们 P0 做不到）。
- **仍然站得住的三格**：① **中文三线表 + 中文期刊口径**（JASP/jamovi 只出 APA 英文表，这恰好是中文用户占比最大的那类需求）；② **目标体系切换**（它们是单一口径）；③ **Methods 段 / 问诊 / 脏表清洗**（它们的 GUI 骨架在结构上装不下）。
- **一条要记住的成本教训**：JASP/jamovi 被社区反复安利的理由**就是"表直出 Word"这一条**（B2 §四的四条用户原声全部指向它）。这说明该痛点的价值判断是对的，只是**我们不是唯一解**——真正的差异化必须落在"中文 + 体系切换 + 脏表 + 问诊"这四个词上，而不是"表能粘进 Word"这六个字。

### 7.2 我们**没有**优势的地方（如实写）

1. **方法覆盖数：完败。** SPSSAU 约 500 类、SPSSPRO 360+ 算法，是十年积累。我们 P0 只有 4 个方法族。**这场军备竞赛不打**（B2 §七1 / B3 §七1）。
2. **跑单个检验的价格：完败。** SPSSAU ¥9.8/24 小时，问卷星的信效度分析**边际价格已经是 0**（B3 §二3）。我们的能力（跑代码 + 出文件）成本远高于跑一个 t 检验，**不能在最贵的能力上开无限免费**。
3. **"和 SPSS 对不对得上"的举证：结构性劣势。** 一旦掉进这个泥潭就是永远只能防守的战争（B3 §七1）。我们的答案是把不可承诺的"正确性"换成可验证的"过程"，但**这是防守话术不是优势**。
4. **图库：完败。** SRplot 单篇被引 **2,423**、Sangerbox 1,219、Majorbio 891（B3 §三，OpenAlex 一手数据）。我们只出"本次分析自然产出的图"。
5. **生信/组学流程：不进场。** 赛道饱和且依赖参考基因组/注释库/算力。
6. **问卷信效度单点：拿不到钱。** 除非一路做到"论文段落 + 返修回合"。
7. **移动端：没有。** 目标用户里有相当一部分是临床医生，深夜用手机的场景真实存在。这是一个已知缺口，不在 P0 解决。
8. **"表单驱动是竞品结构性弱点"这个立论 —— ⚠️ 待验证，不能作为差异化基础。**
   🔴 B2 的事实核查（R-4 / 任务书更正 #19）明确推翻了这条推断：**ChatSPSS 首页第一句就是「像聊天一样完成统计分析：上传 CSV/Excel/SPSS(.sav)/Stata(.dta) 数据**或直接描述研究问题**」**——以自然语言描述研究问题为入口，恰恰绕开了"先选方法"；SPSSPRO 也公开宣称"AI 自动识别数据结构，推荐最佳算法"。
   **在实际注册试用 ChatSPSS / SPSSPRO 之前，不应把"表单驱动"当成竞品的结构性弱点。**
   **行动项：立项前必须实测这两家**（各花 ¥9.8–19.9 注册一天），验的是"它的自然语言入口到底是真能从研究问题推到正确检验，还是套模板"。这是本次调研留下的**最大且最便宜的可补缺口**。

### 7.3 真正站得住的四条

1. **脏数据 → 干净数据这一段，我们能跑代码，它们只能收表。** 所有 L1/L2 平台的入口都是"上传一张干净宽表"——这是它们的产品骨架（算法目录 + 参数表单）**在结构上装不下**的东西。而这恰恰是用户最花时间、代做方明码标价（EBOSS："若数据变更则另外收费"）的那一段。
2. **合规交付物的体系切换。** 收窄到站得住的版本（B1 更正 #10）：**没有任何一家 AI 原生产品提供中文期刊要的三线表 / APA 制式表 / 可直接粘进 Word 的规范化表格 / LaTeX 表格源码**——它们导出的是幻灯片、HTML artifact、图片与 notebook。
3. **数字来源锁 + 过程可复核。** ⚠️ 这是**入场券不是加分项**：Uedufy 已经在拿 "Zero Hallucinations Guarantee" + 7 天退款（覆盖"捏造统计量或引文"）打市场（B2 §Q3）。市场已经把"AI 编数字"认定为这个品类的头号失效模式。
4. **返修回合的成本优势 —— 但"边际≈0"必须拆成两个数，不能囫囵说。**
   代做行业最贵的商品是"不限次修改"（EBOSS 预试套餐 8,000→正式套餐 18,000 的溢价全在这，且明写"如 DATA 更改则增加额外收费"）。我们有会话耐久 + 产物文件 + 幂等 verb，但**两类返修的成本差三个数量级**：

   | 返修类型 | 实际发生什么 | 我们的边际成本 | 溢价文案能不能用 |
   |---|---|---|---|
   | **A · 换格式 / 换体系 / 改表样** | 只重跑 `report` verb（吃同一份 bundle + 新 `--system`），**零 LLM 调用、零重算** | ≈ **0**（秒级 CPU） | ✅ **"不限次"只对这一类成立** |
   | **B · 补一轮分析**（审稿人要敏感性分析 / 加协变量 / 换检验） | 新一轮完整 turn：读回 project.json + 重新问诊/规划 + 跑 verb + 写 Methods | 按 §8.4-$2 的口径 **input 8–20 万 token 量级**，与首轮同量级（省掉的只有 profile 与部分问诊，约 20–30%） | ❌ **不能承诺不限次**；应按"返修包 N 轮"计量，N 用 `project.json.revision_round` 记 |

   🔴 **原稿（以及 §0-4、需求 §5.2③）把这两类合并成"我们的边际返修成本≈0"，与自家 §8.4-$2 的 token 估算直接冲突。** 正确的商业表述是：**"改格式不限次 + 补分析按轮"**——这仍然强于人力代做（对方连 A 类都要重排一遍表，且 B 类是全价重做），但它是一句经得起成本表核对的话。
   ⚠️ 还有一条硬边界见 §8.1-T11：**返修窗口上限 = 会话 workDir 的 30 天 GC**，超期原始数据与产物一起被删。

### 7.4 一个必须内部盯住的天花板

Europe PMC 检索 `"Julius AI"` **命中 53 篇**已发表文献，包括 **PLoS Medicine**（2025-12-05, PMC12680241），其方法学原文是：

> "All the analyses ... were performed using **Stata software, version 17/SE** ... **Data visualizations were performed using Julius AI**"

🔴 **在高分刊里，统计仍然交给 Stata/SPSS，AI 只被允许做"数据可视化"**（B1 更正 #3）。天花板不在"能不能进论文"，而在"**被允许进论文的哪一段**"——而那恰好是我们要争的那一段。这决定了产品的长期叙事必须是"**我按 SPSS 的口径给你算，并且每一步你和你导师都能复核**"，而不是"取代 SPSS"。

## 九 · 明确不做的清单

### 9.1 形态层面

1. **不做通用 BI / 交互式看板 / dashboard / 数据库连接器。** 五个学科集群**全部**独立点名了这一条。医学用户要的是静态的、能贴进 Word 的表和图，审稿人不会点你的筛选器（A1）。
2. **不做"一键出完整分析报告 PDF"。** 用户要的是**按稿件部位切分的可粘贴碎片**；报告形态会被拆开重排，所有格式工作白做。证据：所有付费服务商卖的都是"表格 + Results 段 + Chapter 4 打磨"，**没有一家卖"分析报告"**（A6 §八1）。
3. **不做零代码点选式统计向导。** 那是 SPSSAU/SPSSPRO 主场，交互形态还与 agent 对话式相斥（B3 §七2）。
4. **不做 Excel 插件 / 桌面客户端。** WPS AI 数据助手"只支持 Windows"已经证明桌面端是坑；Numerous.ai 那条路做的是文本活不是统计活（B1 §七10）。
5. **不做"对话里逐轮调参"的长流程。** 一次上传 → 一次问清 → 一次出全套。超过 3 轮往返用户就回去找 ¥100 代做（A1）。
6. **不做人工兜底服务。** mstata / 风暴统计都在用"人工工作室 / 专家验证"补 AI 的洞——能提质但不可规模化，且会把我们变成一家代做公司（B3 §七10）。

### 9.2 能力层面

7. **不自研统计引擎。** 全部走 scipy / statsmodels / lifelines。论文方法学里要写的是"statsmodels 0.14.4"不是"Scholay 内部算法"。
8. **不做"一键跑完整篇论文的统计"。** 没有任何开放式真实分析基准超过 50%（DABstep hard 45.24%、DSBench 34.12%、DiscoveryBench 25%、ScienceAgentBench 32.4%）。一份"看起来完整、实际半错"的报告比没有报告更糟。
9. **不做统计教学。** 中文教程已过剩到饱和（医咖会 61 节 SPSS 教程覆盖 49 种方法、同一个 ROC 截断值有三篇独立教程）。用户不是没看过教程，是看完还是做不出来。只在决策点给一句 20 字理由（A1/A2/A3）。
10. **不做 Meta 分析（本期）。** 工作流完全独立（文献筛选 → 数据提取 → RevMan/Stata → PRISMA 流程图），与"上传一张表做分析"共享不了任何组件。应作为独立卡片单独立项（A1）。
11. **不做组学全流程 / 生信管线。** 美吉、OmicShare、派森诺背靠测序业务可以免费送，我们只会做出更差的版本。只做"公司结果表 → 重画图/改阈值"这一段下游（A3）——**且这一段归科研绘图卡片**。
12. **不做 EEG/ERP/fMRI 原始信号预处理**（GB 级 .bdf/.set/.nii，pipeline 绑死 MATLAB + EEGLAB/SPM）、**不做 GIS 空间统计**（需 shapefile + 坐标系 + 空间权重矩阵，且结果必须落回地图）、**不做谱图分峰拟合**（XRD/Raman/XPS，本质是信号处理，Origin/Jade 路径依赖极强，**做半截比不做更糟**）（A5）。
13. **不做完整 SEM / 路径图**（AMOS/Mplus 路径依赖 + 需画图）。Bootstrap 中介效应可做，完整 SEM 不做（A5）。
14. **不碰 Mplus 深水区**（潜类别 LCA/LPA、交叉滞后 CLPM/RI-CLPM、多层中介、贝叶斯 SEM）：用户量小、正确性风险极高、**错了很难被发现**（A2）。
15. **不做研究级统计**（复杂生存分析设定、层次贝叶斯、因果识别策略选择）。StatEval 显示研究级推理是明确短板，CausalGame 显示只有 5–7% 的会话在因果推理项上得分。**主动拒答并建议找统计学家——"知道自己不该做什么"本身可做成卖点**（B4 §九11）。
16. **不做大数据 / 不抬 30MB 上限接单细胞 GWAS。** 30MB 覆盖了"湿实验 + 问卷 + 临床 + bulk 组学"——**这恰好是"一个人自己做完能发一篇文章"的全部场景**。超过的都需要专门生信/计量流程。正确做法是**清晰拒绝并指向 Seurat/Scanpy**（A7 §四）。
17. **不做 Origin `.opj`/`.opju`**（liborigin 只到 2017 版，2018 起无开源方案，OriginLab 有官方免费 Viewer）、**不做 `.sas7bdat` 写回与 SAS catalog 深度支持**（pyreadstat 写不出 SAS 能读回的文件，SAS 用户在药企/CRO 根本不会往公网传数据）（A7 §七）。
18. **不做 `.spv` 的写回/生成。** 读（翻译成论文段落）价值极高，写只有造假一个用途。**这个不对称必须在设计上锁死**（A7 §七8）。
19. **不做浏览器端"本地分析、数据不出本机"。** Pyodide 装不下 statsmodels/lifelines 的依赖树，且与"agent 在沙箱跑真代码"的架构正交。替代方案是浏览器端只做上传前的标识列体检（A7 §七5）。
20. **不重做绘图引擎、不做图库。** 期刊级图型已被 ImageGP/Hiplot/SRplot/微生信做到引用级。只出"本次分析自然产出的图"（B3 §七4）。

### 9.3 红线层面

21. **不做"让结果变显著"的任何变体**，包括包装成"稳健性检验助手"但实质是穷举模型设定直到 p<0.05（A7 §七7）。
22. **不做"自动在 NHANES/SEER 里换变量找显著结果"的选题器**——这正是 PLOS Biology 定义的 research Mad Libs。**反向做才对**：用户跑了 N 个变量就强制提示 FDR/Bonferroni 校正（A1）。
23. **不做"一键生成 3000-5000 字 SCI 论文初稿"。** 竞品 mstata 已在做，但 PLOS Biology 显示 NHANES 公式化论文中国作者占 92.4%、Science 已公开点名 AI + 公共数据集催生低质论文。**这条路终点是被期刊拉黑与平台连坐**（A1）。
24. **不做"这个结果能不能发/几区"的结论性判断。** 改做"审稿人会问什么"的提问清单——**用提问代替断言**（A6 §八3）。
25. **不生成任何原始研究图像**（显微镜/western blot/影像/图形摘要）。Elsevier 与 Springer Nature 双红线。数据可视化允许、原始图像绝对禁止，**两者在产品里必须是两个入口**（B4 §九5）。
26. **不接收未去标识化的原始病历文本 / DICOM 影像 / 基因原始数据。** 只接结构化且已去标识化的表格（A1）。
27. **不承诺"结果一定正确"、不承诺"全自动"、不承诺"替代 SPSS/统计学家"。** Minitab 官方自己都写"AI technology may make mistakes. It is the user's responsibility to ensure the output is accurate"；Elsevier 政策原文写着 AI "must never be used as a substitute for human critical thinking, expertise and evaluation"。**正确姿态是"每一个数字都能点回去看它是怎么算出来的"**。
28. **不试图说服用户离开 SPSS，也不在文案里贬低 SPSS。** 锁住用户的是导师和院系，任何"取代 SPSS"的叙事都把用户置于跟导师对抗的位置。正确叙事是"**我按 SPSS 的口径给你算，你导师看不出区别**"（B2 §七3）。

### 9.4 两条本次修订补入的裁决（原本证据在 raw 里、却两份 synthesis 都没给裁决）

29. **不做聚类 / 关联规则 Apriori（中医方剂配伍规律、证候研究）。**
    **它本不该是漏项**：A1 §1.1 逐字点名"中医=关联规则/聚类"，A1 矩阵 #12 还给了一手出处（《数据挖掘算法在中药方剂研究中的应用现状》，中国药房）与真实工具链（SPSS Modeler 18.0 + Statistics 25~27 + **Cytoscape 3.9.1** + Excel）。但原稿 43 行需求矩阵里**既没有聚类也没有关联规则**，也没进任何"不做"清单——**证据进了 raw 没进 synthesis**。
    **不做的三条理由**：① **它不是假设检验，是数据挖掘**——没有 p 值、没有前提假设、没有效应量，本方案全部三处"确定性夺权"（前提检验 / 数字来源 / 六项必报）**一条都不适用**，等于在同一张卡片里塞进第二套完全不同的质量体系；② **终点是网络图不是三线表**——支持度/置信度/提升度算完之后，中医论文要的是 Cytoscape 的**复杂网络可视化**，那是"科研绘图"的地盘且需要专门的布局算法；③ **正确性无法自证**——关联规则的输出是几百条规则，"哪些有意义"完全靠中医药领域知识，我们既判不了也担不起责任（与 §九-15"知道自己不该做什么"同一条原则）。
    **正确姿态**：明确拒绝并说明"这类分析建议用 SPSS Modeler / R 的 arules，我们不做"；⚠️ 但**中医研究里的临床疗效比较（组间 t/χ²、量表评分、Table 1）照常支持**——不要把"中医"整个学科拒掉，被拒的只有数据挖掘那一支。
    🔴 **另记一处真实缺席（不是裁决，是承认）**：**药学 / 中医药作为一个学科集群，在本次七份需求侧调研里整体缺席**（全目录 grep：`药学` 0 命中、`网络药理` 0 命中、`中医` 4 次全在 A1 内部）。药学的方法需求（药动学参数、溶出曲线相似因子 f2、稳定性趋势、网络药理学）**既没有被调研也没有被裁决**，属于**已知的调研覆盖缺口**，不是"已评估后决定不做"。若要进这个市场需单开一轮 A8。

30. **不做树模型 + 校准曲线 + SHAP（随机森林 / XGBoost 的"可解释 ML"论文体裁）。**
    **为什么这条必须写理由而不能只写"不做"**：它是**最容易被用户直接问到**的一类（"能不能帮我跑个随机森林"），而拒绝理由**最不直觉**——技术上 sklearn 1.4.2 就在镜像里，跑一个 XGBoost 比跑一个 Welch ANOVA 还容易。所以只写"不做"会被当成能力不足。
    **真正的理由是质量体系不兼容，不是能力不足**：
    - ① **它没有前提检验可守门。** 本方案的核心差异化（"LLM 首要错型 = applicability error × 100% 可机械判定"）在树模型上**整条失效**——树模型没有正态性/方差齐性/独立性可测，我们最值钱的那道闸在这里空转。
    - ② **它的正确性风险转移到了我们判不了的地方**：数据泄漏（预处理放在划分之前）、过拟合（n=200 的临床数据跑 XGBoost）、类别不平衡处理、超参搜索的嵌套交叉验证——这些错误**在输出上全部不可见**（AUC 照样很漂亮），与 §8.2-M4 的伪重复是同一类"程序跑得通、图正常、零警告"的错，但**我们没有对应的确定性闸**。
    - ③ **交付物形态不同**：它的产物是 AUC/校准曲线/SHAP 蜂群图，不是三线表 + Methods 段——**族 4（交付层）这个我们唯一的护城河对它零覆盖**。
    - ④ ⚠️ **需求侧证据本身也弱**：本目录只有两条间接证据（A1 把"机器学习"列为用户不会的一档；B3 记录 SPSSPRO 的算法清单含 XGBoost），**没有任何一手文献计量**。任何"这是增长最快的一类"的说法在本目录里**没有证据支持，不要写进对外材料**。
    **正确姿态**：拒绝 + 指路（sklearn/XGBoost 的标准流程、建议找有 ML 背景的合作者），并说清"我们不做的是建模，不是不会算"。
    **⚠️ 与 LASSO 的区别（不要一刀切）**：**LASSO 变量筛选是 P2 要做的**（见需求矩阵 #45），因为它是**临床预测模型这条链的第一步**（LASSO 选变量 → Logistic/Cox → 列线图 → 校准 → DCA），而那条链的终点（列线图）是 §2.2 认定的最强差异化钩子。**做了链尾却不做链头，等于把链掐头。** LASSO 与树模型的分界线是：**前者服务于一个仍以回归系数与 p 值为交付物的传统统计链，后者要另起一套 ML 质量体系。**

**没有照改的地方（共 3 处，理由如下）**

1. **批评清单第 1 条要求"把 Duncan 与 CLD 标为自写（CLD 需 insert-absorb 算法）"—— 不照改。** 一手核验推翻了这个前提：**scikit-posthocs 0.14.0（MIT）自带 `posthoc_duncan` 与 `compact_letter_display()`**（后者定义在 `scikit_posthocs/_grouping.py`，GitHub 源码直取）。标成自写会凭空多算 2–3 天工期，且会让人错过"这个包同时解决四个缺口"这件事。**批评的核心主张（"库栈里没有实现路径，scikit-posthocs 该被采纳"）完全成立且已全部落实**，被更正的只是自写量的归属。保留的自写项是 **CLD 的大小写双水平合并**（跑两个阈值再合并，包里没有）与 **Welch-ANOVA / 效应量 CI**。
2. **批评清单第 6 条称树模型"是当前中文医学论文增长最快的一类"—— 该行已加，但增速说法不写。** 本目录 13 份 raw 里没有任何一手文献计量支持这个增速（A1 只把"机器学习"列为用户不会的一档，B3 只是抄了 SPSSPRO 的算法清单）。**本报告的既有纪律是"证据强度必须标注、推断不许写成事实"**，照抄这句会在自己最强调的那条纪律上开一个洞。已改为标注"需求强度为推断，硬证据只有两条间接的"，并显式写明**不要引用未经核实的增速**。裁决（不做 + 四条理由）不受影响。
3. **批评清单第 10 条给的"二选一"里，没有选"把场景 B 降级为 P1 走查"—— 选了做。** 理由：批量×合并与字母标记是同一条链上的两块（15 个指标各跑一遍单因素方差 + 字母标记 → 合并成一张大表），A3 把两者一起列为杀手锏；砍掉批量会让"字母标记"这个全案唯一王牌只能一次处理一个指标，实际使用价值大幅缩水。成本也不高（`--batch-key` 是分组循环、`--merge` 是表拼接，已计入重估后的 T2）。**代价已如实计入**：T2 与 T7 各增，总工期 20–26 天。
