### 2.3 apt vs pip 的约定(`Dockerfile:55-77` 明确写死)

1. **能 apt 就 apt**。`python3-scipy` 即使已是传递依赖也要**显式列出**,理由写在 `Dockerfile:55-59`:
   「顺带带进来的包会随上游漂移静默消失,而 SKILL.md 还在承诺它」。
2. **只有 Debian 里没有 / 同名冲突的才 pip**。`Dockerfile:60-62` 记了一个真坑:
   Debian 里叫 `lifelines` 的包是**家谱软件**,装了会得到完全无关的东西。
3. pip 必须:`--break-system-packages --no-cache-dir` + 阿里云 PyPI 镜像 + **钉死版本**,装完 `apt-get purge python3-pip`
   (`Dockerfile:73-75`)。
4. **构建期断言**收尾:`Dockerfile:77` 跑一次 `import` 全家 + `assert numpy.__file__.startswith('/usr/lib/python3/dist-packages')`
   —— 机械保证 pip 没覆盖 Debian 的 numpy。
5. **分层纪律**:每个大依赖单独一层,`Dockerfile:39` / `:68` 反复强调「别合进上面的大层
   (整层重装 Docker Desktop 易 OOM Killed)」。

### 3.1 无开关 + 启动自探

### 3.2 bind 清单(`bwrap.ts:70-124`,逐条)

```
--unshare-all --die-with-parent --new-session --clearenv
--setenv HOME=/work PATH=/usr/local/bin:/usr/bin:/bin TMPDIR=/tmp
--setenv LANG=<容器LANG|C.UTF-8>  TZ=<容器TZ|Asia/Shanghai>
（刻意不挂 /proc —— bwrap.ts:85-90 解释:Docker masked paths 挡住,且实测负载不需要）
--dev /dev
--tmpfs /tmp
--ro-bind      /usr /usr
--ro-bind-try  /bin /lib /lib64
--ro-bind-try  /etc/alternatives     ← libblas.so.3 两跳软链;不 bind 则 import numpy 直接挂
--ro-bind-try  /etc/matplotlibrc     ← 不 bind 则 "Could not find matplotlibrc"
```
