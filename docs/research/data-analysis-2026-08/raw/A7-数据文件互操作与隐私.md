# A7 · 数据文件互操作与隐私合规

> 横切主题调研 · 「数据分析」能力卡片立项
> 调研日期：2026-08-04
> 定位：**这一节决定工程可行性边界。** 不谈「用户想要什么分析」，只谈「用户手上的文件物理上长什么样、我们的容器能不能打开它、打开之后合不合法」。

## 〇、结论先行（读完这七条可以不读正文）

1. **`.sav` / `.dta` / `.sas7bdat` 现在在我们的上传闸门里是被硬拒的。** 本仓库 `backend/internal/agentattach/upload.go:330-367` 的白名单里没有任何统计软件原生格式，`.xls` 还被 `isLegacyOfficeExt` 显式拒收。「数据分析」卡片如果不改这个白名单，用户第一步就撞墙。
2. **`.sav` 的可读性是好消息**：pyreadstat（Apache 2.0，底层 ReadStat 是 MIT）能完整读出变量标签、值标签、用户缺失值区间、measure、display width。中文变量名在 SPSS 里通常只活在**变量标签**里（变量名会变成 `VAR00001`），这份元数据读不到就等于丢掉用户最核心的资产。
3. **`.spv`（SPSS 输出文件）是被严重低估的切入点。** GNU PSPP 的 `pspp-output` 已经能把 SPV 转成 csv/html/txt，PSPP 开发者文档基于约 8000 个真实文件逆向出了完整格式规格。这意味着「把你已经跑好的 SPSS 结果翻译成论文段落」是**技术上可行、且不需要用户交出原始数据**的路径——这条路同时绕开了本节后面所有的隐私问题。
4. **`.xlsx` 我们「能收」但读法有三个致命降级**：`agent/src/tools/xlsx2text.py` 用 `read_only=True`（合并单元格信息丢失）+ `data_only=True`（文件没被 Excel 打开保存过时，所有公式格返回 `None`），输出走 stdout 8MB 闸 + 60s 超时。这三条恰好精准命中真实脏数据的三种最常见形态。
5. **合规上最锋利的一条是「人遗信息」而不是「个人信息」**：《人类遗传资源管理条例实施细则》第二条明确把「基因、基因组数据」列为人遗信息、把「临床数据、影像数据、蛋白质数据和代谢数据」**排除在外**。也就是说——组学数据出境要向科技部事先报告并提交备份，而一张临床病例表不受人遗条例管（但仍受 PIPL 管）。这条边界必须写进产品文案，因为它是绝大多数用户搞不清的。
6. **界面上必须写的只有三句话**（不是三段）：数据存在哪、留多久、会不会用于训练。SPSSAU 的隐私页把这三句写得很直白（阿里云 RDS、用户可自行删除且不可恢复、未提及用于训练），这是国内学术用户已经被建立起来的预期基线。
7. **灰色需求是真实且有规模的，必须有硬拒设计。** 荷兰全国科研诚信调查（n=6813，PLOS ONE 2022-02-16）：8.3% 承认伪造或篡改过数据，生命与医学领域 10.4%；51.3% 频繁做过至少一项 QRP。新京报 2024-05-21 卧底论文工厂拿到的写手原话是：「像这种论文，必须要有数据支撑，但作者又没有提供，你只能编数据喽。」我们的卡片一旦上线，这类请求一定会来。

## 一、文件格式全景与读取现实

### 1.1 SPSS `.sav` —— 元数据才是资产

**能读到什么。** pyreadstat 是 ReadStat C 库的 Python 封装（与 R 的 haven 同源），返回的 metadata 对象包含：列名与列标签（`column_names_to_labels` 映射）、`variable_value_labels`（变量名 → {值: 标签} 的字典）、`missing_ranges`（用户自定义缺失值区间，每项含 `lo`/`hi` 边界）、file label、file encoding、notes、原始变量类型/格式、以及 SPSS 特有的 measure（nominal/ordinal/scale）与 display width。
来源：[Roche/pyreadstat GitHub README](https://github.com/Roche/pyreadstat)，实测抓取于 2026-08-04；[pyreadstat 文档 1.3.4](https://ofajardo.github.io/pyreadstat_documentation/_build/html/index.html)。

**为什么元数据是核心资产。** 经管之家（原人大经济论坛）SPSS 版块的老帖「用SPSS输入变量时为什么不能输入中文变量名」下，被采纳的处理方式是：**变量名用英文或数字，中文写在「变量标签」里**。
来源：[bbs.pinggu.org/thread-3035829](https://bbs.pinggu.org/thread-3035829-1-1.html)。

这条对我们是决定性的：一个中国用户的 `.sav` 文件里，`a1 a2 a3 q12_1` 这种变量名毫无语义，**「您的最高学历」「术后 30 天再入院」这些中文全部只存在于 variable label 里**。任何用 `pandas.read_spss()` 之后只拿 DataFrame、丢掉 metadata 的实现，等于把用户的数据变成一堆无名列——AI 会立刻开始瞎猜列的含义，这是幻觉的机械成因，不是模型不聪明。

同理，值标签（`1=男 2=女 9=拒答`）不读进来，AI 就会把编码当成数值去算均值。

**已知坑。**
- `pandas.read_spss()` 底层就是 pyreadstat，但它默认只返回 DataFrame；要拿元数据必须直接调 `pyreadstat.read_sav()`。
- 用户缺失值默认被翻译成 `NaN`；要拿到原值必须显式 `user_missing=True`。**这个默认值很危险**：SPSS 用户常用 `99 / 999` 做缺失码并在 SPSS 里登记为 user missing，默认读法会把它们静默变 NaN（正确），但如果用户**没在 SPSS 里登记**（很常见），999 就会作为真实数值进入均值计算（灾难）。
- 部分损坏的 SAV 文件缺行数元数据。
- 极端日期（年份超过 10000）会触发 `OverflowError`。
来源：同上 pyreadstat README。

**中文乱码。** 经管之家 2012 年的帖子「无法读入含有中文的文件名；值和标签里的中文显示乱码」到 2015 年还有人在跟帖给方案（改字体为 Simsun / 升级 SPSS 版本）——说明这是一个横跨十年、至今没被根治的用户体验。
来源：[bbs.pinggu.org/thread-1323249](https://bbs.pinggu.org/thread-1323249-1-1.html)，首帖 2012-01-17，末条回复 2015-11-23。
对我们的含义：读 `.sav` 时不能相信文件里声明的编码，需要在 GBK/GB18030/UTF-8 之间做探测与兜底。

**许可证。** pyreadstat = Apache 2.0；底层 ReadStat = MIT。两者都允许商业使用、无 copyleft 传染。
来源：[pyreadstat README](https://github.com/Roche/pyreadstat)。**这是所有候选方案里许可证最干净的一条路。**

### 1.2 SPSS `.spv`（输出文件）—— 被低估的低门槛切入点

**结论：可解析，且有成熟工具。**

`.spv` 本质是一个 Zip 归档。PSPP 开发者文档（基于对约 8000 个真实 SPV 文件的逆向）写得很明确：

> "An SPV file is a Zip archive that can be read with `zipinfo` and `unzip` and similar programs."

归档内的结构成员命名为 `outputViewer<10位数字>.xml` / `outputViewer<数字>_heading.xml`，每个成员代表一个输出项（表、标题、文本块）。表格数据有两种载体：新版是单个 `prefix_lightTableData.bin`（结构+数据合一的二进制），旧版是 `prefix_table.xml` + `prefix_tableData.bin` 配对。
来源：[GNU PSPP 开发者指南 · SPSS Viewer File Format](https://www.gnu.org/software/pspp/pspp-dev/html_node/SPSS-Viewer-File-Format.html)。

命令行工具 `pspp-output convert` 可以把 SPV 转成 csv / html / txt / odt / pdf / svg 等。
来源：[Ubuntu manpage: pspp-output](https://manpages.ubuntu.com/manpages/jammy/man1/pspp-output.1.html)。

**已知坑（PSPP 文档自己写的）：**
> "SPSS tolerates corrupted Zip archives that Zip reader libraries tend to reject."
即：SPSS 自己能打开的文件，标准 zip 库可能直接拒绝。需要容错解压。

**许可证风险。** PSPP 是 GPLv3。**以子进程方式调用 `pspp-output` 二进制不构成链接**，不会传染到我们的后端代码；但如果把它打进 Docker 镜像分发，需要在合规上确认（对 SaaS 场景通常无义务，GPLv3 无 AGPL 的网络条款）。**建议：以 CLI 子进程方式调用，绝不用 FFI 链接 libpspp。**

**为什么这是最好的第一刀。** 它解决了本节后面所有的隐私问题：`.spv` 里没有个案数据（micro-data），只有汇总表。用户上传的是「我已经算好的结果」，不是「我的病人名单」。产品话术可以直接是——

> 「不想传原始数据？把 SPSS 跑完的输出文件（.spv）传上来，我帮你翻译成论文的 Results 段落。」

这一句同时命中：低门槛、零隐私顾虑、明确的成品。**置信度：高（格式可解析已由 PSPP 文档与 CLI 双重证实）；未核实的是 `pspp-output` 对中文 SPV 的输出保真度——需要拿真实中文 .spv 实测。**

### 1.3 SPSS `.sps`（语法文件）

纯文本，UTF-8 或 GBK。零解析难度。价值在于：`.sps` 是用户过往分析的**完整可复现记录**，读它可以知道用户的方法学习惯、变量重编码逻辑、他上次做了什么检验。低成本高信息密度，建议直接进白名单当纯文本读。

### 1.4 Stata `.dta`

**版本与编码是核心矛盾。** DTA 118（Stata 14+）和 119（Stata 15+，支持 >32767 个变量）才是 Unicode；**118 之前的版本文件不声明文本编码**，默认编码随平台而异。
来源：[haven::read_dta 文档](https://haven.tidyverse.org/reference/read_dta.html)：

> "Prior to Stata 14, files did not declare a text encoding, and the default encoding differed across platforms."
> haven 在 `encoding = NULL` 时假定 windows-1252；Mac/Linux 上产生的老文件建议试 `latin1`。

**对中文的含义**：中国经管/社科用户手上有大量 Stata 12/13 时代的 `.dta`，中文标签是 GBK 裸字节。用 windows-1252 或 latin1 读都会得到乱码，而 ReadStat 遇到无效字节序列会直接抛 `ReadstatError: Unable to convert string to the requested encoding (invalid byte sequence)`。
来源：[WizardMac/ReadStat Issue #239](https://github.com/WizardMac/ReadStat/issues/239)。

**实现要求**：读 `.dta` 必须做「先试 UTF-8 → 失败退 GB18030 → 再失败退 latin1 并告知用户」的三级探测，而不是让 ReadStat 抛异常就完事。

**方案**：pyreadstat（Apache 2.0）读 118/119 无碍；R 侧 readstata13 覆盖 102–121 更全但我们容器里没有 R（见 §2.3）。
来源：[readstata13 CRAN README](https://cran.r-project.org/web/packages/readstata13/readme/README.html)。

### 1.5 SAS `.sas7bdat` / `.xpt`

pyreadstat 可读 sas7bdat、sas7bcat（格式目录）、xport。值标签存在**独立的 catalog 文件**（`.sas7bcat`）里，需要用 `set_catalog_to_sas` 或读取时传 catalog 参数才能挂上。

**已知坑（pyreadstat 文档自述）：**
- SAS catalog 文件「有些只能在特定 SAS 版本里读，且可能有奇怪编码，很多 catalog 文件 pyreadstat 读不了」。
- 很多 SAS 日期时间格式（YEAR、MMYY）不会自动转换，需要显式传 `extra_datetime_formats`。
- 老 xport 文件含非 ASCII 字符时必须手工指定编码。
- **pyreadstat 无法写出 SAS 能读回去的 sas7bdat**（这是 ReadStat 的固有限制）。
来源：[pyreadstat README](https://github.com/Roche/pyreadstat)。

**产品含义**：SAS 用户几乎都在药企/CRO/大型医院统计室，他们的数据合规约束最严（见 §5），基本不会往公网 AI 传。**优先级最低。** 支持 `.xpt`（FDA 提交格式，通常是脱敏后的）比支持 `.sas7bdat` 更有意义。

### 1.6 GraphPad Prism `.pzfx` / `.prism`

**只能读一半。** Prism 5 起数据以 XML 存在 pzfx 文件里，且 GraphPad 官方明确这是「为自动化数据操作准备的」。但——

> "After the XML data portion comes information about results, graphs and layouts in a format that is incomprehensible to any program but Prism."
（XML 数据段之后是结果、图形、版式信息，格式对 Prism 之外的任何程序都不可理解）
来源：[GraphPad FAQ 913](https://www.graphpad.com/support/faq/prism-integrated-saves-prism-files-instruments/) 与 [Prism 用户指南 PZF vs PZFX](https://www.graphpad.com/guides/prism/latest/user-guide/pzf_vs__pzfx_file_format.htm)。

**即：能拿到数据表，拿不到他跑过的分析结果和图。** 这和 SPSS 的 .sav/.spv 分工正好相反。

开源方案：[ulido/pzfx_parser](https://github.com/ulido/pzfx_parser)（MIT，11 stars，16 commits——**维护度极低，属于「读一读源码自己实现」级别，不建议直接依赖**）；R 侧有 CRAN 上的 `pzfx` 包。

另注：**Windows 版 Prism 用 XDR schema、Mac 版用 W3C XML Schema**，两边 XML 结构不同，需要分别处理。
来源：[GraphPad FAQ 1638](https://www.graphpad.com/support/faq/prism-xml-style-sheet-and-schema-that-define-the-pzfx-format/)。

**受众判断**：Prism 是生物医学湿实验的绝对主力（细胞/动物实验、剂量反应曲线）。这批人**数据量极小**（常常是 3×6 的表），痛点不在「算不出来」而在「不知道该用哪个检验 / 图不好看」。支持 pzfx 的 ROI 主要在「省掉手工敲数据」，不在数据规模。

### 1.7 Origin `.opj` / `.opju`

**旧格式能读，新格式基本读不了。** liborigin 支持 3.5 到 2017 版本的 `.opj`。
来源：[liborigin @ SourceForge](https://sourceforge.net/projects/liborigin/)；Python 封装见 [Saluev/python-liborigin2](https://github.com/Saluev/python-liborigin2)；R 侧 CRAN 有 `Ropj`。

Origin 2018 起的默认格式是 `.opju`，liborigin 邮件列表里 OPJU 支持长期是未解决状态。
来源：[liborigin-devel: Re: OPJU support](https://sourceforge.net/p/liborigin/mailman/message/36989709/)。

**建议：不做。** 详见 §七。Origin 用户主要在材料/物理/化学，他们的诉求是画图不是统计推断，且 OriginLab 官方提供免费 Origin Viewer，用户导出 CSV 的路径通畅。

### 1.8 Excel / CSV —— 90% 的现实

这是绝大多数用户的实际载体，也是脏数据的重灾区。展开在 §三。

一个必须知道的硬数字：Excel 单工作表上限 **1,048,576 行 × 16,384 列**，单元格最多 32,767 字符，工作表数量受内存限制。
来源：[Microsoft · Excel specifications and limits](https://support.microsoft.com/en-us/office/excel-specifications-and-limits-1672b34d-7043-467e-8e27-269d656771c3)。

## 二、我们自己的工程现实（本仓库实测）—— 这一节是可行性的真实边界

这是本次调研最重要的一节，因为它是**唯一不依赖外部信源、可以被立刻验证**的部分。

### 2.1 上传闸门：统计软件原生格式现在全部被拒

`backend/internal/agentattach/upload.go` 的白名单（2026-08-04 实测）：

- `isPlainText`：`.md .markdown .txt .log .json .jsonl .xml .yaml .yml .csv .tsv .sql .sh .py .js .ts .tsx .jsx .go .rs .c .cpp .h .hpp .java .rb .php .tex .bib`
- `isOffice`：`.docx .xlsx .pptx .odt .rtf`
- `isLegacyOfficeExt`（**显式拒收**）：`.doc .xls .ppt .ods .odp`

**`.sav` / `.dta` / `.sas7bdat` / `.xpt` / `.pzfx` / `.spv` / `.opj` 一个都不在白名单里，会走 switch default 被拒。**

这个白名单遵循的原则写在文件头注释里，值得原样引用（它是我们自己的铁律）：

> 白名单原则（2026-07 文件上传调研）：**收 = 能读**。凡容器内没有解析路径的格式（旧版 doc/xls/ppt、ods/odp、bmp、svg）一律在入口拒收并给出用户可执行的指引，绝不让"传上去了 AI 却打不开"的断层发生。

**含义**：扩白名单和装解析器必须**同一次上线**。先放行再补库 = 制造断层，违反已确立的铁律。

### 2.2 `.xlsx` 读取路径的三个致命降级

`agent/src/tools/xlsx2text.py`（实测全文 30 行）核心是：

```python
wb = load_workbook(sys.argv[1], read_only=True, data_only=True)
for ws in wb.worksheets:
    out.write(f"=== Sheet: {ws.title} ===\n")
    for row in ws.iter_rows(values_only=True):
        cells = ["" if v is None else str(v) for v in row]
```

三个降级，每一个都精准命中一种真实脏数据：

**降级一：`read_only=True` → 合并单元格塌成空。**
openpyxl 只读模式返回 `ReadOnlyCell`，不是常规 Cell；合并区域信息不可用。合并单元格的效果是**左上角有值、其余全 None**，被上面的代码转成空字符串。用户表格里典型的「组别」列（三行合并成一个"对照组"）会变成「对照组 / 空 / 空」——AI 看到的是缺失值，不是分组。
只读模式的另一个官方警告：工作表 dimension 信息「有些应用程序设置得不正确」，需要 `ws.calculate_dimension()` 校验、`ws.reset_dimensions()` 修正。
来源：[openpyxl 文档 · Optimised Modes](https://openpyxl.readthedocs.io/en/stable/optimized.html)。

**降级二：`data_only=True` → 公式格可能全是 None。**
官方文档原文：

> "data_only controls whether cells with formulae have either the formula (default) or the value stored the last time Excel read the sheet."

关键推论：**如果这个文件从未被 Microsoft Excel 打开并保存过（例如由 WPS、Google Sheets、某台仪器、某段 Python 导出），缓存值不存在，所有公式格返回 `None`。**
来源：[openpyxl 教程 · Loading from a file](https://openpyxl.readthedocs.io/en/stable/tutorial.html)。

中国用户大量用 WPS。一张「均值/标准差在最后一行用公式算」的表，从 WPS 存出来传给我们，**最后一行会整行是空的**，而 AI 完全不知道那里本来有值。

**降级三：输出是 TSV 文本，走 stdout 8MB 闸 + 60s 超时。**
（限制记录在 `xlsx2text.py` 头注释与 `registry.ts` 的 `runConverter`。）一张 10 万行的表转成 TSV 轻松超过 8MB，会被静默截断——AI 拿到的是**半张表**，而它不知道自己只拿到了半张。

**这三条合起来的结论：现有的 xlsx 通道是为「读文档」设计的，不是为「做数据分析」设计的。** 数据分析卡片必须走**另一条读取路径**（直接 `pandas.read_excel` / `pyreadstat` 在沙箱内读原文件），而不是复用 ReadDocument 的文本抽取。这是本次立项最重要的一条工程结论。

### 2.3 沙箱：断网 + `/usr` 只读 = 依赖必须构建期就位

`agent/Dockerfile` 实测已装（2026-08-04）：
`python3-numpy` `python3-scipy` `python3-pandas` `python3-matplotlib` `python3-statsmodels` `python3-sklearn` `python3-openpyxl` `python3-docx` `python3-rdkit` `libblas3` `liblapack3`，pip 装 `lifelines==0.30.3`，vendor pandoc 3.10.1，weasyprint。

**未装：`pyreadstat`、`R` / `Rscript`、PSPP、`xlrd`（.xls）、`pyarrow`（parquet）。**

Dockerfile 里的这段注释是本次立项的直接依据（它已经在讲一次同类事故）：

> 事故背景：agent-skills/claw-add/guides 的 methods-stats/SKILL.md 与 data-figures/SKILL.md 向模型声明「claw 能用 python（statsmodels）真算」……而镜像里 statsmodels / sklearn / lifelines **根本没装**（2026-08-01 容器实测）。用户要混合效应模型 / Cox 回归时，模型只剩「撞 ImportError」或**把数字编出来**两条路 —— 后者正是审计中效应量凭空出现的机械成因。

并且 `agent/src/tools/statsEngines.ts` 已经建了一套启动期探测（`DECLARED_ENGINES` → `engineSupported`），设计意图写得很清楚：**「装上了」不等于「运行期真能 import」**，因为真实链路是 Bash → wrapBash → buildBwrapArgv 进 jail，jail 的 bind 集漏一个运行库就 ImportError。

**所以：`pyreadstat` 一旦要装，必须 (a) 写进 Dockerfile 构建期，(b) 加进 `DECLARED_ENGINES`，(c) 让探测结果驱动「能不能收 .sav」的真值。** 运行期 `/usr` 只读 + 无 pip + 断网，装不了任何东西。

`methods-stats/SKILL.md` 里已经明确写了本环境的边界，这段话在数据分析卡片上线后需要同步扩写：

> **本环境没有的：** 没有 R / Rscript。可以给用户 R 代码带走自己跑，但那段代码**在这里没有被执行过**，说清楚。

## 三、真实脏数据形态

### 3.1 Excel 自动改数据 —— 有硬数字的那个

最著名、也最有说服力的案例：Excel 把基因名当日期。`SEPT2`→`2-Sept`、`MARCH1`→`1-Mar`、`Oct-4` 同理。

**2016 年**《Genome Biology》估计约 20% 含 Excel 基因列表的论文有此错误。
**2021 年**的扩大复查更糟：扫描 2014–2020 年 PubMed Central 上 166,139 篇基因组学论文，其中 32,841 篇带 Excel 补充文件、11,117 篇有基因符号列表——**30.9%（3,436 篇）含基因名错误**，分布在 5,086 个电子表格里。错误率超过 40% 的期刊包括 *Cell*、*Nature*、*PNAS*、*Cell Reports*、*Oncogene*。
来源：Abeysooriya, Soria, Kasu, Ziemann, [*PLOS Computational Biology*, 2021-07-30](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1008984)。

作者在 The Conversation 上的解释直指机制：

> "If you type in a phone number starting with zero, it will recognise it as a numeric value and remove the leading zero."
> "If you type '8/2' it will be recognised as a date."

以及为什么十几年了还没解决：

> "researchers and journals were largely unaware of the autocorrect problem and how to avoid it."
来源：Ziemann & Abeysooriya, [The Conversation, 2021-08-26](https://theconversation.com/excel-autocorrect-errors-still-plague-genetic-research-raising-concerns-over-scientific-rigour-166554)。

后果严重到 HGNC（人类基因命名委员会）直接给基因改名：MARCH1→MARCHF1、SEPT1→SEPTIN1。

**对我们的产品含义**：这不是「用户不小心」，这是**软件默认行为造成的系统性污染**。数据分析卡片在读入表格时应当做一次「可疑类型转换」体检：日期型的列里出现 `1-Mar` 且同列其它值是基因符号、前导零丢失、身份证/编号被转成科学计数法。**这个体检本身就是一个可展示的价值点**，因为它是确定性的、不需要模型推理、且用户从来没人替他做过。

### 3.2 结构性脏（按危害排序）

以下形态从上文来源与我们自己的读取路径分析交叉得出：

1. **合并单元格作为分组标记**——被 `read_only=True` 塌成 None（§2.2）。中文表格里极常见（「组别」「时间点」「科室」）。
2. **多行表头**——第一行大类、第二行子项，第三行才是数据。CRAN 的 `unheadr` 包专门为此存在（"unwrapping values broken up across rows and relocating embedded grouping values"）。
   来源：[unheadr @ CRAN](https://cran.r-project.org/web/packages/unheadr/)。
3. **一个 sheet 放多组实验**——中间用空行隔开，或者「第一组」「第二组」写在某个单元格里当小标题。程序看到的是一张有很多空行和莫名文本行的表。
4. **中文列名带空格 / 单位混在列名里**——「体重(kg)」「体重 (kg) 」「术前体重kg」在同一份数据的不同 sheet 里指同一个变量。
5. **日期被 Excel 改成序列号**——`2024-03-01` 变成 `45352`；或反过来，`3/1` 被认成日期。
6. **缺失值混编**——`999` / `NA` / `N/A` / 空格 / 空字符串 / `无` / `-` / `—` 在同一列里共存。SPSS 用户尤其爱用 `9 / 99 / 999`，因为 SPSS 有 user-missing 机制；导出成 CSV 后这个机制**丢失**，999 就变成了真实数值。
7. **宽表/长表混乱**——重复测量数据写成 `T0 T1 T2 T3` 四列（宽表），但用户想做的混合效应模型需要长表；或者反过来。
8. **同一变量单位不统一**——mg/dL 与 mmol/L 混在一列；身高有的填 175 有的填 1.75。
9. **公式列在 WPS 导出后为空**（§2.2 降级二）。

**置信度**：3.1 的数字是高置信度（同行评议论文）。3.2 的清单里 1/2/5/6/9 有直接来源支撑，3/4/7/8 是从来源与工程分析推出的常识性形态，**未找到直接量化统计**，标为中置信度。

## 四、文件体积与行列量级的真实分布

**这一节我必须诚实：没有找到「中文学术用户上传数据的行列分布」的公开统计。** 下面是可核实的锚点 + 明确标注的推断。

**硬锚点（可核实）：**
- Excel 单表上限 1,048,576 行 × 16,384 列。（Microsoft 官方，见 §1.8）
- 我们的单文件上限 30 MB。（本仓库实测）

**量级推断（低到中置信度，需实测校准）：**

| 场景 | 典型规模 | 30MB 够不够 |
|---|---|---|
| 湿实验（Prism 类） | 3–8 组 × 3–20 重复 | 远远够（KB 级） |
| 问卷/量表（社科、护理、公卫） | 200–2,000 行 × 30–200 列 | 够（`.sav` 通常 < 5MB） |
| 单中心临床回顾性研究 | 100–1,000 行 × 30–150 列 | 够 |
| 多中心 / 队列 | 数千–数万行 | 通常够，CSV 可能到 10–50MB |
| 面板数据（经管） | 数万–数十万行 × 20–80 列 | **边缘**，CSV 常超 30MB |
| bulk RNA-seq 表达矩阵 | ~2 万基因 × 10–100 样本 | 够（几 MB～几十 MB） |
| 单细胞矩阵 | ~2 万基因 × 数千–数十万细胞 | **远远不够**（GB 级，且真实格式是 `.h5ad`/`.rds`/`.mtx`，不是表格） |
| GWAS | 百万级 SNP | **完全不适用** |

**产品结论（这是本节唯一真正有用的部分）：**
30 MB 覆盖了「湿实验 + 问卷 + 临床 + bulk 组学」这四类——**这恰好是「一个人自己做完能发一篇文章」的全部场景**。超过 30MB 的都是「需要专门生信/计量流程」的场景，那不是能力卡片的战场。

**不要为了支持单细胞/GWAS 去抬上限。** 抬上限只会带来 OOM、超时和一个永远做不好的场景。正确做法是**明确的拒绝文案**：「你这份是单细胞矩阵，超出了本工具的设计范围，建议用 Seurat/Scanpy 流程」——比勉强收下然后跑崩强一百倍。

## 五、隐私与合规硬线

### 5.1 中国 · 人类遗传资源管理条例（最锋利的一条线）

《人类遗传资源管理条例实施细则》（科技部令第 21 号，2023-05-26 公布，**2023-07-01 施行**）：

**第二条**——人类遗传资源信息定义：「利用人类遗传资源材料产生的人类基因、基因组数据等信息资料」，**「不包括临床数据、影像数据、蛋白质数据和代谢数据」**。

**第三十六条**——向境外组织、个人及其设立或实际控制的机构提供或开放使用人类遗传资源信息的，中方信息所有者应当「向科技部事先报告并提交信息备份」，报送事项包括目的用途、信息及备份情况、接收方基本情况、风险评估。

**第三十七条**——可能影响公众健康、国家安全的，应通过科技部组织的安全审查。

**第十四条**——国际合作中，中方单位应「全过程、实质性地参与研究」，所有记录和数据信息应「完全向中方单位开放，并向中方单位提供备份」。

来源：[科学技术部令第21号 · 人类遗传资源管理条例实施细则](https://www.most.gov.cn/xxgk/xinxifenlei/fdzdgknr/fgzc/bmgz/202306/t20230601_186416.html)。

**这条边界必须写进产品，因为它是绝大多数用户搞不清的：**
- 一张临床病例表（年龄、性别、检验值、结局）→ **不属于人遗信息**，不受出境事先报告约束（但受 PIPL 管，见 5.2）。
- 一个基因型/表达谱矩阵 → **属于人遗信息**，向境外提供须事先报告+备份。

⚠️ **口径冲突记录**：某律所解读文章称「临床数据属于人类遗传资源信息的范畴」，与第二条原文相反。经核查该文标题为《……实施细则（**征求意见稿**）要点评析》，属定稿前的草案评述（同文提到的「采集审批门槛 3,000→10,000 例」亦为草案口径）。
来源：[汉坤律师事务所](https://www.hankunlaw.com/portal/article/index/cid/8/id/16574.html)。**以科技部定稿原文为准，该律所解读标为低置信度、不采用。**

### 5.2 中国 · PIPL 与去标识化/匿名化的分水岭

这是产品文案里最容易被写错的一条：

- **去标识化**：不借助额外信息就无法识别特定个人。**去标识化后的信息仍是个人信息**，仍受 PIPL 全部约束，**包括数据出境规则**。
- **匿名化**：无法识别特定个人**且不能复原**。匿名化后的信息**不属于个人信息**，不受 PIPL 约束。

来源：多份实践指南解读汇总，代表性讨论见 [安全内参 · 十问十答看懂我国个人信息去标识化规则](https://www.secrss.com/articles/31527) 与 [个人信息匿名化制度的反思与改进](https://www.secrss.com/articles/70304)。（原文页面 2026-08-04 实测返回 403，结论来自检索结果摘要，**标为中置信度**。）

**产品含义**：我们**绝不能**在文案里写「已脱敏 = 安全」。「脱敏」在法律上通常只到去标识化，仍是个人信息。正确的话术是描述事实（「数据存在境内 X，保留 Y 天，不用于训练」），而不是给用户一个法律定性。

### 5.3 GDPR / HIPAA

**GDPR 第 89 条**（科研目的处理的保障与减损）要求「有技术和组织措施到位，特别是为确保数据最小化原则得到遵守」，并写明「这些措施可以包括假名化，前提是这些目的能以该方式实现」。
来源：[GDPR Article 89](https://gdpr-info.eu/art-89-gdpr/)。

关键点：**假名化（pseudonymisation）不等于脱离 GDPR**，与中国的「去标识化」逻辑一致。

**HIPAA**：Safe Harbor 的 18 类标识符移除法是美国医学数据脱敏的事实标准。**本次未能核实 2025-2026 年各大学对「向 LLM 上传 PHI」的具体禁令文本**（尝试抓取的两个高校政策页分别返回 404 与 403）——标记为**未核实**，见 §八。

### 5.4 期刊与出版方政策（2025-2026）

**ICMJE**（当前版本，页面 © 2026）原文：

> "Authors who used AI technology to conduct the study should describe its use in the methods section in sufficient detail to enable replication of the approach, including the tool used, version, and prompts where applicable."
> "humans are ultimately responsible for reviewing and ensuring the accuracy of any content generated with assistance of AI."
> "Authors should not list or cite AI and AI-assisted technologies as an author."
> "Editors, reviewers, or publishers should not upload submitted manuscript into AI systems where confidentiality cannot be assured without authors' explicit permission."

来源：[ICMJE Recommendations · Use of Artificial Intelligence](https://www.icmje.org/recommendations/browse/artificial-intelligence/) 与 [Manuscript Preparation](https://www.icmje.org/recommendations/browse/manuscript-preparation/preparing-for-submission.html)。

**分工非常清楚：写作辅助 → 致谢；用 AI 做研究（含数据分析）→ 方法学部分，且要写清工具、版本、prompt。**

其他出版方（2025-2026 状态，中置信度，来自二手汇总）：
- Elsevier 2025-09 更新：AI 披露须放在参考文献前的独立小节；明确禁止 AI 生成图像。
- Springer Nature：区分 AI 辅助文字编辑（无需披露）与生成式 AI 工作（须披露）。
- The Lancet：AI 使用仅限于改善可读性与语言。
- BMJ、AACR、Elsevier 系刊：投稿系统里已有强制的 AI 使用问项，与正文披露不一致会触发编辑质询。
来源：[Enago · Publisher AI Policies and Disclosure Rules](https://www.enago.com/responsible-ai-movement/resources/publisher-ai-policies-disclosure-rules-authors)、[thesify · AI Policies in Academic Publishing 2025](https://www.thesify.ai/blog/ai-policies-academic-publishing-2025)。（二手汇总，**未逐条回原文核实，标为中置信度**。）

**产品含义（这是一个功能，不是一句免责声明）：**
用户用我们做完分析，投稿时**必须**在 Methods 里写清工具+版本+prompt。**我们应当自动生成这段可粘贴的方法学披露文本**——包含：调用的统计库及版本（`statsmodels 0.x`、`lifelines 0.30.3`）、执行的具体检验、以及一句符合 ICMJE 措辞的 AI 使用声明。这是竞品普遍没做、成本极低、且直接解决用户真实焦虑的东西。

来源：[spssau.com/privacy.html](https://spssau.com/privacy.html) 与 [spssau.com/secruity.html](https://spssau.com/secruity.html)
→ 值得注意：SPSSAU 的隐私政策**通篇未提及是否将用户数据用于模型训练**。这是一个空白，也是我们可以明确占据的位置。

### 5.6 产品侧应当承诺什么 · 界面上必须写什么

**必须写的（三句话，放在上传控件旁边，不是放在设置里的隐私政策）：**

1. **存在哪 + 存多久**：「数据只存在会话工作目录，会话删除即删除；服务器在中国境内。」（对应用户原声里最高频的「出境」恐惧）
2. **不用于训练**：「你上传的数据不会用于训练任何模型。」（SPSSAU 都没写，写了就是差异化）
3. **一键删除**：可见的「删除本次数据」按钮，且明确「删除后不可恢复」。（SPSSAU 已经把这个预期建立起来了，我们必须有）

**必须做的（不是承诺，是功能）：**

4. **上传前的本地体检 + 脱敏建议**：在浏览器里读表头，识别出疑似 `姓名 / 身份证 / 手机 / 住院号 / 门诊号 / 病案号 / 联系方式 / 地址` 的列，**在上传前**弹一句「检测到 3 列可能含个人标识，建议删除后再上传」并提供一键删除。这比任何隐私声明都有说服力，而且成本极低。
5. **人遗信息提示**：识别到数据形态像基因型/表达矩阵时（列名大量是基因符号 / rsID），给一条提示：「基因、基因组数据属于《人类遗传资源管理条例》规定的人类遗传资源信息，向境外提供须事先报告。本平台数据不出境。」——这一条同时是合规声明和差异化卖点。
6. **自动生成 ICMJE 合规的方法学披露文本**（见 5.4）。
7. **「不传原始数据也能用」的入口**（`.spv` / 已有结果表 / 只贴描述统计），把隐私顾虑最重的用户接住。

**不该写的：**
- 不写「符合 GDPR」——除非真的做过 DPA 与数据映射，写了是虚假陈述。
- 不写「已脱敏所以安全」——去标识化在 PIPL 下仍是个人信息（§5.2）。
- 不写「银行级加密」这类无信息量的话，用户已经免疫了。

## 六、数据造假 / p-hacking 的灰色需求

### 6.1 规模：有数字，不小

**荷兰全国科研诚信调查**（n=6,813 完成问卷 / 63,778 份邀请，2022-02-16 PLOS ONE，Gopalakrishna 等）：
- 伪造（fabrication）：**4.3%**（95% CI 2.9–5.7）
- 篡改（falsification）：**4.2%**（95% CI 2.8–5.6）
- 二者合计至少一项：**8.3%**；**生命与医学科学领域 10.4%（最高）**
- 频繁做过至少一项 QRP：**51.3%**
- 原文结论句：「One in two researchers engaged frequently in at least one QRP, while one in twelve reported having falsified or fabricated their research at least once.」
来源：[PLOS ONE, 2022-02-16](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0263023)

**生态与进化生物学者调查**（n=807，Fraser 等 2018，PLOS ONE）：
- 看了显著性之后再补数据：生态 36.9% / 进化 50.7%
- 看了对显著性的影响之后再剔除数据点：24.0% / 23.9%
- 因为不显著而没报告结果：64.1% / 63.7%
- HARKing（事后假设当预设）：48.5% / 54.2%
来源：[PMC6047784](https://pmc.ncbi.nlm.nih.gov/articles/PMC6047784/)

**中国的产业化端**：
央视 2025-10-12 曝光：商家用「论文查重」作商品名规避审查，「为规避审查双方聊天不能涉及'论文'字眼」；采用「组稿+AI」模式，一人一天可完成 30 篇；消费端报价「几千元到上万元不等」，写手端「在群里仅仅标价几百元」；某网店代写商品「年销量已经超过40000单」。
来源：[腾讯新闻转央视报道，2025-10-12](https://news.qq.com/rain/a/20251012A05XPK00)

新京报 2024-05-21 卧底论文工厂，**写手原话**：
> 「像这种论文，必须要有数据支撑，但作者又没有提供，你只能编数据喽。」
> 「不用管质量，用AI写，万字论文一下午就搞定了。」
> 培训课程中演示者「让AI模拟参考文献的格式，随机编了一些参考文献」，并称「80%的人不会去查参考文献的真实性」。
> 价格：文科万字论文中介开价 300–500 元；专科/函授约 200 元；理科需画图做程序才超过 500 元。
来源：[新京报，2024-05-21](https://news.sina.cn/2024-05-21/detail-inavyqqp0030093.d.html)

法律侧：2021 年修订的《科学技术进步法》明令禁止学术论文买卖、代写、代投；2022 年科技部等二十二部门《科研失信行为调查处理规则》明确买卖/代写/代投论文属科研失信行为。
来源：印波（中国政法大学），《警惕论文代写黑灰产升级迭代》，法治日报/江苏检察网，[2025-10-27](https://www.jsjc.gov.cn/shzs/fzzc/202510/t20251027_182130.shtml)

### 6.2 关键区分：三层，不是两层

**这是本节最重要的设计洞察。** 大部分「帮我把 p 值调显著」的请求，用户自己并不认为是造假——因为**方法学文献里确实写着这些做法**。

CSDN 上一篇讲「解决回归系数不显著」的实证研究文章（2026-08-03）给出的清单是：换模型、换变量指标（「同一个财务变量，可能有多个指标能衡量」）、样本处理（「删除ST、PT公司，删除交叉上市的公司，删除IPO当年的数据，删除资不抵债的公司，对离群值进行Winsor处理」）、检验异方差与自相关。作者的自述很坦率：

> 「在我做实证的经历中，不显著是常态，显著反而稀缺。」
来源：[CSDN 博客，2026-08-03](https://blog.csdn.net/2301_79384104/article/details/132231081)

**这些做法本身没有一条是非法的。** 它们变成 QRP 的唯一分水岭是：**做了之后报不报**，以及**是先定规则还是先看结果**。

所以正确的三层模型是：

| 层 | 定义 | 例子 | 我们的动作 |
|---|---|---|---|
| **L1 合法方法学调整** | 有预设依据、且会被报告 | 按预注册标准剔除、Winsor、换非参检验、多重比较校正 | **正常做**，并自动记录进分析日志 |
| **L2 灰区（QRP）** | 做法本身合法，但**依据是「结果好不好看」**、且**不打算报告** | 「试试删掉这几个离群值看 p 会不会掉下来」「换个自变量指标试试」 | **做，但强制留痕 + 主动提示** |
| **L3 明确造假** | 改数值、编造观测、直接改 p | 「把 p 改成 0.03」「再给我生成 20 个病人」 | **硬拒** |

L2 是最大的一块，也是最有产品价值的一块——**因为我们可以在这里做一件人类统计师做不到的事：完整、自动、不可篡改的分析尝试日志。**

### 6.3 硬拒边界与话术设计

**必须硬拒（L3），无例外：**
1. 直接修改数据值以改变检验结果（「把这三个数改大一点」）。
2. 生成/补齐不存在的观测（「我样本量不够，再造 30 例」）——**注意这与「生成模拟数据用于教学/功效分析」的合法请求只有一字之差**，判据是：**产物是否会被当作真实观测使用**。
3. 直接编造统计量（「就写 p<0.05」「给我一个 OR=2.3 的结果」）。
4. 反向搜索式剔除（「一个一个删，删到 p<0.05 为止」）。
5. 伪造数据来源/伦理批件/参考文献。

**话术设计原则（三条，都来自本仓库已确立的心法「让正确的路更便宜，而不是罚得更重」）：**

**原则一：不说教，直接给替代路径。**
「这个我不能做」之后必须紧跟一条**用户当下就能走**的路。空的拒绝会把用户推去淘宝，那里 300 块就能买到（§6.1）。

拒绝话术模板（L3）：
> 「改数值这一步我不做——这会让整篇文章在任何一次原始数据核查里崩掉，代价不是退稿是撤稿。
> 但你现在的情况我能帮上：
> ① p=0.06 且方向一致时，报**效应量 + 95% CI**比报 p 更有说服力，很多期刊现在更认这个；
> ② 我可以算一下当前样本量下的实际功效，如果是 power 不足，这是一个可以写进 Limitations 的**正当理由**；
> ③ 如果你的数据是重复测量/嵌套结构而现在按独立样本在算，换成混合效应模型本身就可能改变结论——这是方法学修正，不是调数。
> 要走哪条？」

**原则二：L2 不拒绝，但强制留痕并说出来。**
用户说「试试删掉这两个离群值」——我们**照做**，但同时：
- 在产物里生成一张「分析尝试记录表」（做了什么、之前 p、之后 p、剔除依据）；
- 输出一句：「已按你的要求剔除 2 个观测（ID 17, 43）。提醒：如果剔除依据是『看了结果之后』而不是预设的离群值规则，投稿时需要在 Methods 里说明剔除标准与剔除数量——STROBE/CONSORT 都要求这个。我已经把两版结果都留在报告里了。」

这比拒绝有用一万倍：**它把 QRP 变成了「可报告的敏感性分析」**，这正是方法学家希望发生的事。

**原则三：绝不假装做了。**
最危险的失败模式不是拒绝，是**模型答应了然后编数**。Dockerfile 注释里已经记录过一次同类事故（声明有 statsmodels 实际没装 → 模型编数）。所以：
- 任何统计量必须来自**真实执行过的代码**，代码与输出一并展示；
- 库缺失/执行失败必须如实说「跑不了」，不允许降级成叙述性数字；
- 这条应当接上已有的 `statsEngines.ts` 探测真值与证据账本机制。

**边界的边界（不要过度拒绝）：**
- 「生成模拟数据练手/演示/做功效分析」——**合法，要做**。
- 「我的结果不显著，怎么写讨论」——**合法，要做**，这是最常见也最正当的求助。
- 「多重比较校正后全没了，还能怎么办」——**合法**，这是方法学问题不是造假。
- 「帮我把图做好看点」——**合法**，与数据无关。
过度拒绝会把大量正当用户误伤，且会让「数据分析」卡片显得不可用。判据始终只有一条：**是否改变了对真实观测的忠实呈现。**

## 七、我们不该做什么（砍需求）

1. **不做 Origin `.opj` / `.opju`。** liborigin 只到 2017 版，2018 起的 `.opju` 无开源支持；受众（材料/物理/化学）的诉求是画图不是统计推断；OriginLab 有官方免费 Viewer，用户导 CSV 路径通畅。做了是纯负债。

2. **不做 `.sas7bdat` 写回、不做 SAS catalog 深度支持。** pyreadstat 明确写不出 SAS 能读回的 sas7bdat；catalog「很多读不了」。SAS 用户在药企/CRO，合规上根本不会往公网传数据。**最多支持 `.xpt` 只读。**

3. **不抬 30MB 上限去接单细胞/GWAS。** 见 §四。抬上限换来的是 OOM、超时、和一个永远做不好的场景。正确做法是清晰拒绝 + 指向 Seurat/Scanpy。

4. **不复用现有 ReadDocument 的 xlsx 文本抽取通道做数据分析。** §2.2 的三个降级会系统性地把合并单元格、WPS 公式列、大表后半段变成静默的空白。必须走独立的读取路径。

5. **不在浏览器端做「本地分析、数据不出本机」。** 听起来是隐私杀手锏，实际上 Pyodide 装不下 statsmodels/lifelines 的完整依赖树，性能不可控，且与我们「agent 在沙箱里跑真代码」的整个架构正交。**替代方案是浏览器端只做上传前的标识列体检（§5.6 第 4 条），轻量、有效、不改架构。**

6. **不写「符合 GDPR / HIPAA」的合规宣称。** 没做过 DPA、数据映射、BAA 就写，是虚假陈述，风险远大于收益。只陈述可验证的事实（境内、不训练、可删除）。

7. **不做「一键让结果显著」的任何变体**，包括看起来无害的包装（「稳健性检验助手」如果实质是穷举模型设定直到 p<0.05）。这是产品的道德底线，也是长期品牌的唯一护城河——竞品在这条线上只要越一次，我们就赢了。

8. **不做 SPSS `.spv` 的写回/生成。** 读（翻译成论文段落）价值极高；写（生成一个假的 SPSS 输出文件）只有一个用途，就是造假。**这个不对称必须在设计上就锁死。**

9. **不做数据脱敏的「保证」。** 可以提供辅助工具（识别标识列、建议删除），但绝不能说「脱敏后就安全了」——去标识化在 PIPL 下仍是个人信息。工具帮忙，责任在用户，这一点必须说清楚。

## 八、缺口与存疑（未核实项，不要当结论用）

1. **`pspp-output` 对中文 `.spv` 的保真度未实测。** 格式可解析是确定的（PSPP 文档 + CLI 双证），但中文表头/值标签经转换后是否乱码、透视表结构是否保留，**必须拿真实中文 .spv 跑一次**才能立项。这是 §0 结论 3 唯一的风险点。

2. **HIPAA / 美国高校 2025-2026 对「向 LLM 上传 PHI」的具体禁令文本未取到。** 两次尝试抓取高校政策页分别返回 404 / 403。当前只能确认 Safe Harbor 18 标识符这一通用框架。**对我们影响不大**（主力用户在国内），但如果要做海外版必须补。

3. **Reddit 全线不可访问**（r/AskStatistics、r/labrats、r/PhD、r/bioinformatics 均被 UA 拦），**知乎全线 403**。原定的英文与中文用户原声主渠道两条都断了。现有 5 条原声来自百度知道、CSDN、新浪、新京报、SPSSAU 隐私政策——**质量可用但渠道偏媒体化，缺少「学生在深夜论坛里的原始抱怨」这一层**。建议后续用人工浏览器补采 3–5 条。

4. **「中文学术用户实际上传数据的行列/体积分布」无公开统计。** §四的量级表是锚点 + 推断，**必须在卡片上线后用我们自己的埋点校准**（记录行数、列数、文件大小、格式的分位数）。这是上线后第一周就该有的数据。

5. **SPSSPRO 的上传限制、定价、隐私条款未取到**（首页无此信息，未深入其帮助中心）。SPSSAU 的取到了。竞品的具体行列上限对我们定上限有参考价值，属可补缺口。

6. **各出版方 2025-2026 AI 政策为二手汇总**（Enago / thesify），ICMJE 是一手原文。Elsevier「2025-09 更新」「独立小节」、Lancet「仅限可读性与语言」等具体条款**未回原文核实**，若要写进产品文案必须逐条回官网确认。

7. **Excel 脏数据形态清单（§3.2）中 3/4/7/8 项无量化来源**，属工程常识性归纳，中置信度。若需要对外引用应补一手来源或改为定性表述。

8. **`.sav` 里 user-missing 未登记的情况有多普遍**——即「用 999 当缺失但没在 SPSS 里声明」的比例——**没有数据**。这直接影响我们要不要默认对 `9/99/999/-999` 做主动询问。建议上线后统计。
